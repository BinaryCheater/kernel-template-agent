# WP23 delivery: deployment modes, measurement exclusivity, staged queues, role work units

Branch `wp/WP23` from `integration` (c62842c). Code stage (D320) plus the real Part E deployment. Decisions D600–D619.

## What was done

**Part A — topology (D600–D602).** One compute host, spark-hk, for every CPU and GPU job; two modes as `config/modes/dev-mac.toml` (control plane and agent CLIs on the Mac, agents through Clash, jobs to spark-hk over ssh) and `config/modes/spark-hk.toml` (everything on spark-hk, local workers, proxy off), selected by `KTA_MODE` (`KTA_CONFIG` still wins). The store follows the control plane: `kta store backup <dir> [--handover <to>]` and `kta store restore <dir>`; a handed-over store refuses to start the API and processes. `agent_user` is optional (empty = the user's own account). Docs: design 11 §1.1, §4, §5; conventions §6; D300 and D592 marked superseded in the decision log and review queue.

**Part B — measurement exclusivity (D603–D608).**
- Host readers–writer lock `kta.core.hostlock` (two flock files: a turnstile for writer preference and the lock itself; bounded waits; max hold with forced release). The worker takes it shared for cpu and gpu-shared jobs and exclusive for self-leased gpu-exclusive jobs; `quiet_lease` holds it exclusive for the whole window through a `hold` worker process, so other control planes on the host drain too; in long-run mode the in-process MIP solve takes it shared (`[host] lock_dir`). Lock waits are `lock_wait` spans on `host:<worker>`.
- Quiet-host verification: the timing job records host readings before warm-up and around the measured loop (/proc CPU of other processes, load, memory; NVML utilisation, memory, compute processes, clocks, temperature, throttle reasons). Beyond `measure.quiet_thresholds` (default, set by X6; X6 gains the arm agents idle vs active) the attempt is written as a Report `measurement_interfered`, rerun, and never becomes a Measurement; all attempts interfered → `HostNotQuiet` (infra).
- Unified-memory cap for concurrent cpu jobs (`execution.unified_memory_cap`, default 48 GB / 4 GB per job, `set_from: S0 data`).
- Measurement batching windows (`measure.batch_window`, `MeasureWindow`).

**Part C — stage queues (D610–D613).** `orchestrator/stage_queues.yaml` (intake → generate → build → check → ready_to_measure → measure → judge → analyse) with capacities from `pipeline.stage_capacity` (Settings, set by X12); `stagequeue.plan` gives backpressure, unblock-first order and measurement windows; `solve_tick` uses it. `GET /trace/stages` and the Pipeline page's "Stage queues" panel show depth, throughput and wait per stage over time, GPU busy and host-lock waits, plus held loops with reasons.

**Part D — work unit = case × role (D614–D615).** `orchestrator/work_units.yaml` (kernel T1/T6, model T4/T5, knowledge T2/T3), knob `session.work_unit_rule` (step / case / case_role, default case_role; X3 gains the three arms with tokens per accepted task, acceptance rate and model-blame share). `TaskQueue.create` writes `<loop>:<role>` into the card; the ops row keeps the loop. `/workflow` shows the rule and the role table.

## Fixtures and simplifications

None in `src/` (no `# kta:fixture`). Simplifications:
- Without `[measure] window_worker` each measurement takes its own lease (no batching); both mode files set it.
- L2 simulation has no in-process control-plane call site, so only the MIP solve is wrapped in the shared host lock (D604).
- The memory cap counts only cpu-pool jobs (as the user asked); gpu-shared jobs are not capped.

## Known issues

- `measure/scripts/torch_bench.py` (eager baselines, in a container without `kta`) records no host readings: its timings are `verified: false` and still counted (D605, review queue).
- Agent task order (`quotas.order_queued`) has no unblock-first key; only loops do (D613).
- spark-hk registers without `backend.tilelang`: the user is not in the `docker` group (system change, not done; D619).
- No backup schedule; slai unreachable from spark-hk (D609).
- Codex/Claude subscription credentials are not linked into `~/.config/kta/auth/<provider>` on spark-hk, so an agent launch there would report "not logged in" (no model call was in scope).
- The operator token on spark-hk is at its spec location `~/.config/kta/operator-token` (the only file outside `~/kta`).
- `config/kta.toml` still names the old `spark`; use `KTA_MODE` (D600, review queue).
