## Known issues

- Rounds before the current one count builds, checks and measurements through record edges; a cached Build can carry Checks of other runs, so old rounds may be over- or under-counted (D662). A round id on Candidates would fix it.
- `advance` runs steps on a thread of the API process; restarting the API mid-step leaves the loop lock to expire (the runner's normal lease) and the step is retried by the next advance.
- A per-case `Run` resumes only that loop; the top-line switch starts the process. A process started from the frontend runs inside the API and ends when the API restarts.
- Pages out of the menu (Running, Inbox, Operations, Agents, Experiments, Improvement, Mechanisms, Model scoreboard) still exist by URL; deleting them needs earlier WPs' gate checks changed.
- The journal reads at most `max(400, 40 × limit)` rows per source per page; a burst larger than that splits across pages.
- The record drawer cannot show blobs when the API runs on a store copy without `objects/`.
