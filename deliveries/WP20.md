## Design interrogation

Full pass on the spec interface changes (Issue severity; T2 `admission` done-check and `warnings.yaml`; `kta.knowledge.admission`; Reference schema 2; coverage `learning`; `kta.knowledge.ablation`; `learning_plan.plan` and `kta reference plan|admit`).

### A. Language gaps (D560)

1. **What:** an Issue the expression language or its vocabulary cannot avoid; not an error (the object is wrong) and not a warning (the author must justify).
2. **Claim:** coverage is honest about the structure (21 §2.4); a language limit does not block knowledge entry (D-open-2).
3. **Depends on:** given — the parser's messages name unsupported constructs. Assumption — `p.*` names unknown to a Pattern are vocabulary gaps more often than typos.
4. **Holds:** Templates and chains; Realisation validation is not classified (its issues keep their severity).
5. **Fails:** a typo hides as a gap; an agent writes sloppy expressions knowing they pass; a table regex catches a real error.
6. **Observable:** `language_gaps_by_kind` and per-reference counts on the coverage page and in each admission Report; growth of gaps per reference.
7. **Knob:** the `admission` table rows (data).
8. **Repair:** move a row back to `warning`; extend the language/vocabulary and the gap count drops.
9. **Who:** assistant default per D325 (needs review); alternative: keep `undeclared_pattern_param` a warning and require 61 explanations.

### B. Admit step and `warnings.yaml` (D561)

1. **What:** deterministic validation of a reference directory before it enters the pool; not the T3 Template check (drafts are validated, not written).
2. **Claim:** agent output enters the store only through checks (01 §3 "agents game checks"); a warning is a decision someone owns.
3. **Depends on:** given — the queue retry path and session resume (WP6, WP9a). Assumption — the issue key `<kind>@<file>:<where>` is stable between attempts.
4. **Holds:** T2 deliverables and directory imports; T3 keeps its own duplicate-explanation rule.
5. **Fails:** explanations copied boilerplate ("ok"); a warning key changes between attempts and the agent loops; a pool change between attempts creates new warnings.
6. **Observable:** done_checks Reports per attempt; `admission` Reports with explanations; escalation after 2 retries; repeated identical failure resets the session (existing rule).
7. **Knob:** `max_retries` (2, existing Settings; registry `admit.max_retries`).
8. **Repair:** a human reads the explanation in the Report and rejects the task; the agent revises.
9. **Who:** assistant default (needs review); alternative: explanations in a delivery-note section (harder to match per warning).

### C. Reference schema 2 (D564)

1. **What:** source class and priority inputs on the Reference; not a computed priority (the value is derived).
2. **Claim:** "what to learn next" from data (21 §3, 02 §8.3).
3. **Depends on:** assumption — the four boost reasons and their weights; inputs are filled by a human or a later process (no producer yet).
4. **Holds:** every Reference; v1 reads as `open_code`, no priority.
5. **Fails:** priority inputs never filled (all 0); weights game ordering.
6. **Observable:** `Plan.priority`; references with `priority: null`.
7. **Knob:** `priority.boosts` table.
8. **Repair:** new Reference record version with inputs; table edit.
9. **Who:** assistant default; alternative: a separate Priority record (avoids the schema bump; harder to query).

### D. Coverage levels, system features, backends (D563, D567)

1. **What:** four SOTA levels, counts kept apart from scheduling moves, and backend realisability; not a performance claim.
2. **Claim:** 02 §8.1 "level 1 does not imply level 3"; coverage must not lie by counting system features.
3. **Depends on:** given — Reconstructions, admission and o12 Reports. Assumptions — regex classification of prose; `any` realisations are not backend code.
4. **Holds:** the latest Reconstruction per reference.
5. **Fails:** keyword misclassification; levels 2–4 shown as 0 read as "failed" rather than "not run".
6. **Observable:** per-feature counts; each pending level shows its reason (D320).
7. **Knob:** `system_features`, `sota_levels`, `backends` tables; ε.
8. **Repair:** set `pattern_guess: system`; table edits; real runs fill levels 2–4.
9. **Who:** assistant defaults; alternative: an UnmatchedTx field (schema 3).

### E. Ablation (D566)

1. **What:** a design generator and estimator on our families; not ablation of the reference's code.
2. **Claim:** coupling is local and first-class (O2, `coupled_with`).
3. **Depends on:** assumptions — multiplicative single effects in time; suspected pairs catch the real couplings; 5 % exceeds noise.
4. **Holds:** factors with two levels; chains whose steps can be dropped (the generator must support it — pending).
5. **Fails:** couplings outside suspected pairs missed; fractional aliasing confounds two-factor interactions; noise reads as coupling.
6. **Observable:** each Coupling's `joint_ratio`, `noise_band`, evidence; design mode and aliases in the plan.
7. **Knobs:** `pairwise_max_runs` 32, `max_runs` 64, `noise_band_rel` 0.05.
8. **Repair:** the promotion/demotion engine (WP14) demotes a Coupling on counter-evidence; widen suspects.
9. **Who:** assistant default (needs review); alternative: full factorial on all steps (cost exponential).

### F. Dry-run plans and O12 (D568, D569)

1. **What:** job/variant definitions and an acceptance-experiment protocol; not execution.
2. **Claim:** the learning loop is automated (02 §8.6); reachability is tested blind (O12).
3. **Depends on:** assumptions — a reference build provides `run.sh`; the solve pipeline can build family variants.
4. **Holds:** git sources; runnable references on the target.
5. **Fails:** a plan that never runs is mistaken for a capability; plan argv drift from real tooling.
6. **Observable:** `dry_run: true`; expand loop NotSupported naming the plan; gate WARN for pending real runs.
7. **Knob:** tier rules and source-class stages (data).
8. **Repair:** first real intake on spark corrects the job list.
9. **Who:** assistant default per D320/D325.
