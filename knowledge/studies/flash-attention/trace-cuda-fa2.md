# CUDA FA2: random replay, cache updates and deterministic partials

The full FA2 CUDA family is registered by setup.py:409-495 and generated by
csrc/flash_attn/src/generate_kernels.py: forward/backward/split forward,
head sizes32/64/96/128/192/256, FP16/BF16 and causal variants. Paths below
are relative to the [retained tree](inputs/sources.json). This is evidence for
the pinned source, rather than an assumption that the earlier seed is unchanged.

## Representative and shared choices

Use head128 FP16 on SM80 as the representative. Without dropout the launcher
selects forward128x64 with four warps; dropout selects128x32. SM86/89 have
a different non-dropout tile menu, including128x32 noncausal and64x64 causal
(flash_fwd_launch_template.h:245-274 under csrc/flash_attn/src/). These are
compiled/dispatch choices with source performance comments, not measurements.

## Two independent dropout refinements

[counter_indexed_mask_replay@1](delta/counter_indexed_mask_replay@1/template.yaml)
saves a descriptor rather than the full random mask. Source dropout.h:14-46
under csrc/flash_attn/src/ uses base+(batch*heads+head)*32+lane as offset,
the pair(row_block16,col_block32) as a64-bit subsequence, and a fixed byte
component of each four-word generator output. philox.cuh:34-56 performs six
keyed rounds and one final round. The name Philox does not license substituting
ten rounds. flash_api.cpp:508-516 reserves batch*heads*32 offsets once under
the generator lock. Forward src/flash_fwd_kernel.h:73-86 saves seed/offset
before its first row early exit; backward src/flash_bwd_kernel.h:448-449,
537-545 reads that checkpoint. The backward MMA tile can differ, so its warp
row/column offsets and strides decode the original canonical16x32 block.
For query35,key77 that block is(2,2). Native per-element lane/byte agreement
is still an implementation obligation, not proved by this coarse coordinate.

[sign_embedded_predicate@1](delta/sign_embedded_predicate@1/template.yaml)
is a separate representation choice. dropout.h:26-33,77-80 can store kept
probabilities as +P and dropped probabilities as -P. Forward's optional
returned diagnostic uses it; ordinary PV receives zeroed dropped weights.
Backward keeps signed FP32 P and constructs a separate ReLU-converted
FP16/BF16 operand for dV. The signed copy remains available for dS.

Let q be the source keep-rate scale and M its replayed discrete mask. Forward
O=sum(P*M*V)/q, while LSE still normalizes unmasked P. For incoming g, define
the saved center d=q*dot(g,O). Backward's signed c=+P/-P evaluates
c*(a-d) for c>=0 and c*d otherwise, where a=dot(g,V). This equals
P*(M*a-d); the final1/q factor gives dZ=P*(M*a/q-dot(g,O)). dV uses M*P
and scales by1/q. Source src/flash_bwd_kernel.h:584-595,682,728-733 places
these keep/score scales at their final consumers. The non-dropout row-center
Template does not supply this stochastic derivative by itself.

At keep q=0.5, P=(1/4,3/4), V=(2,6), g=2 and M=(1,0), forward O=1,
saved d=1, and score derivatives are(1.5,-1.5). A dropped nonzero P still
contributes the negative center term; setting the entire dS of dropped keys
to zero is wrong. At P=0, both signed branches produce zero for finite a,d,
so numerical comparison's inability to distinguish -0 is harmless for these
derivative/kept-payload consumers. A diagnostic that needs the exact mask at
zero must inspect the sign bit instead.

The source threshold is floor(q*255) and keep is random_byte<=threshold
(flash_api.cpp:143-150,src/dropout.h:70,80). For q=0.9, threshold229 admits
230 of256 ideal uniform bytes. Scaling by the requested q is part of the
source's discrete operation; exact replay does not establish ideal real-valued
Bernoulli unbiasedness. The [logical check](checks/check_dropout_replay.py) and
[observations](checks/check_dropout_replay.json) retain source integer replay,
reordered canonical blocks, round-count/threshold separation, signed zero and
the fixed-mask finite-difference derivative. Native generator/lane lowering,
graph capture and packed f16x2 comparison remain named obligations.

## Cache append and rotary differences

flash_api.cpp:1246-1510 under csrc/flash_attn/ selects the split/cache kernel
for new KV, cache_batch_idx or paging. Append writes cache positions
[old_length,old_length+new_length), then attends the updated sequence. The
input length array is metadata supplied by the caller, not an automatically
committed new length. Paging uses page sizes divisible256; a page-table view
is incompatible with cache_batch_idx in this entry. Graph capture skips the
host max-length capacity check, so replay capacity remains a caller invariant.

src/flash_fwd_kernel.h:685-790 copies V and optionally rotates K before
writing the cache. Interleaved rotary pairs(2i,2i+1); contiguous rotary pairs
(i,i+rotary_dim/2), with the same two-dimensional rotation arithmetic in
src/rotary.h:20-99 onward. A pair(a,b),cos0,sin1 becomes(-b,a); changing
pair layout changes which features are rotated. Only the appended logical
rows and rotary prefix are transformed, with no zero-fill beyond valid global
destinations. Q positions at src/flash_fwd_kernel.h:795-830 start at old cache
length+leftpad; causal/local mode adds query row, while noncausal mode broadcasts
one position to all queries. This broadcast is an explicit caller convention.
Page translation reuses indexed_gather@1 for reads; append is a mutating write
and needs a separate ownership/publication binding.

The source comment at src/flash_fwd_kernel.h:690-693 permits all CTAs of
one KV head to write identical cache bytes so each can proceed after its own
local barrier. Record this as an unresolved cross-CTA write/visibility contract,
not proof that equal data removes a memory-model race. The public Python
wrapper also documents nondeterministic updates for repeated cache_batch_idx.
No unrelated bug investigation or native safety claim is attached to this study.

## Backward ownership and deterministic alternative

src/flash_bwd_launch_template.h:73-124 launches preprocess, KV-owned backward
and dQ postprocess. src/flash_bwd_kernel.h:826-838 visits key tiles with
n=blockIdx.x+j*gridDim.x. Ordinary mode atomically adds all dQ contributors
to one shared FP32 scratch. Deterministic mode allocates a distinct scratch
slice per grid-x owner, fixes its within-owner tile traversal and sums those
slices later; it does not use the Hopper semaphore scheme. reduction_partition@1
assignment strided_threads gives the contributor grouping, and
split_combine_kernel@1 mode add supplies a second-kernel sum once scratch
layout/order is bound. Extra scratch scales with owner count, which is derived
from SM count and batch/head work in this launcher. dK/dV reduce over grouped
query heads in their own output conversion. Native partial-layout and rounding
bindings remain open; the distinct deterministic organization is accounted for.
