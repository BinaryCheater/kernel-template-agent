## Warp routing by sorted heads

`jit/csrc/moe/route_warp.cuh:194-418,520-542` assigns one warp per token, compiling either one or four warps/CTA. E must be divisible32, E/32<=16,K<=32,K+shared<=32; input vectors use the widest aligned divisor of lane-local L=E/32 within the platform vector limit. Current launch dispatch uses one-warp CTAs while all tokens fit one occupancy wave, four-warps otherwise. This is a heuristic and cached occupancy query, not a performance result of this study. `output_tiling@2` binds one token point/warp (tile_m1,tile_n1,executor=warp,index_map=identity), then one/four token points/CTA. Padded request rows emit invalid expert IDs and zero weights (MuseSpark's caller has a separate weight contract).

For a concrete finite-input E256,K8,G8,TG4 sigmoid route, each lane has L8 experts. Biased rank score=sigmoid(logit)+correction_bias; emitted route weight uses the original unbiased sigmoid. Every four-lane group ranks by the sum of its top two biased expert scores; keep four groups, resolving equal group score by smaller group ID. This group constraint is a workload routing rule, not an equivalent substitute for unconstrained global top8. Group2-max merging preserves two real score occurrences, including equal values. K must not exceed the surviving expert capacity.

Exact within-support selection reuses provisional `sorted_run_topk@1`: run_length8,k8,p.run_capacity8,p.requested_k8, disjoint32 lane runs and smallest original expert-ID ties. Source sorts keys only, offers lane heads to a warp max and chooses the lowest lane holding the max. It recovers the original expert index after selection by scanning saved unsorted keys and skipping earlier equal-key pops of the same lane. Contiguous lane ID ranges make lower lane then lower local index exactly the global smallest-ID order. Equal-key pops from one lane remain consecutive, because a still-equal head keeps winning against later lane IDs. Source retains only min(L,K) usable heads; dropping further local heads is safe because no global topK can need more than K values from one run. Exhausted/taken and group-dropped sentinels are below every real finite key; signed zero is canonicalized. Source floors NaNs to a chosen finite score, which is outside this finite-input rule binding unless that transformed-score workload is explicitly selected.

`checks/route_heads.json` exhaustively replays repeated keys, original-ID recovery and every K through eight values. It also checks the declared bank-group address model below; it does not validate numerical scoring or generated instructions.

Weights are distinct workload recipes: sigmoid/sqrtsoftplus rank with correction bias but weigh without it; softmax ranks and weighs biased logits. Renormalized softmax needs only selected exponentials, while unrenormalized softmax sums all expert exponentials. MuseSpark sums selected weights in selection order and uses scale/(sum+eps), with optional global→local expert mapping; the generic path uses a warp sum and zero-sum/epsilon guard. Shared experts are appended as separate output slots. BF16 packed output stores expertID in high16 bits and rounded weight bits in low16; ID range and invalid sentinel are format premises. No approximation claims are inferred from source comments about PTX ex2/rcp/sqrt or the sqrtsoftplus polynomial.

Two shared lane-major arrays keep original values and unsorted keys. For L8, pitch12 words; for L16,pitch20. `physical_storage@1` binds level=smem,buffer=dedicated,share_order=none. `shared_resource_binding@1` binding=padding names address(warp,lane,j)=warp*32*pitch+lane*pitch+j. Under declared32 banks×4 bytes and16-byte per-lane vector accesses, each eight-lane128-byte phase visits all eight four-bank groups (odd pitch in16-byte units). The host address check supports that conditional binding; arbitrary selected-lane scalar lookup and compiler vectorization do not inherit a blanket conflict-free claim. Hardware queue_depth remains hw.smem_queue_depth, not a tuning variable.

## Merged MoE front: source dispatch read, device epilogue pending

`ops/moe/moe_front.py` merges gate and latent down-projection weights over the same BF16 hidden input, performs one GEMM with FP32 output, then launches one top-k/cast epilogue from `route_radix.cuh`. Fixed source case has896 experts,top16,hidden7168,latent3584. Routing must see the FP32 gate slice; BF16 latent output is made dense for its consumer. This is a shared-input contraction merge plus heterogeneous output slices, not a license to round router logits early. Default dispatch uses merged front through1024 tokens, unfused beyond; device tables may opt exact token counts into stream overlap. Epilogue tuning uses lower token buckets and controls224/448 threads, cast vector8 and before/after placement. Source timing tables are not measurements made here. The selected device epilogue and overlap synchronization must still be read before extracting these choices.

## SM100 expert-specialized grouped GEMM: local offset/dispatch read

`jit/csrc/moe/expert_specialization/es_sm100_mxfp8_blockscaled_moe_group_gemm{,_functor,_traits}.cuh` declares weights A[experts,M,K], packed token B[tokens,K], output[tokens,M] and distinct per-expert token and scale-row offsets. One thread/expert precomputes B=base+expert_offset*K, SF_B=base+blockscale_offset*(K/32), D=base+expert_offset*M. Tokens_per_expert supplies ragged N per group; M is output features. K%128=0 and scaleK=K/32. Mixing scale-row and data-row offsets would address the wrong generation.

The local builder selects SM100 blockscaled E4M3 with FP32 accumulation, BF16/FP16 identity conversion epilogue, MMA tile256x128x128, two-SM MXF8/F6/F4 ptr-array TMA schedule and runtime preferred cluster4x1x1/fallback2x1x1. Stage count is auto after epilogue shared-memory carveout. Those are actual declared backend bindings, not a read of the generated dependency pipeline. The JIT dependency resolver obtains CUTLASS headers from installed FlashInfer data or a configured fallback; the AOT CMake independently pins another CUTLASS archive. These dependency revisions cannot be silently equated. Need one pinned dependency witness (without reopening the paused CUTLASS study) or an explicit external-body boundary, plus the local group quantizer/packing producer.
