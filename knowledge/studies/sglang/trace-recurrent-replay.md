## Fold every commit

`ops/attention/linear/kda_replayssm_spec_decode.py`:39–196 owns one value tile, request, packed(layer,HV) per Triton program. ## Lagged checkpoint with output-only verification

`ops/attention/linear/gdn_replayssm_spec_decode.py`:52–479 implements the distinct circular mode. The physical checkpoint can lag the logical accepted state. `write_pos` counts committed records after checkpoint, `cache_base` maps logical log positions to a power-of-two circular allocation; tentative verify records beyond write_pos are not committed merely because they were stored.

The kernel projects checkpoint and retained key history onto current Q/K. Scalar decay prefix weights update those projected states. For the new window it forms strictly lower A_ij=beta_i*exp(G_i-G_j)*dot(k_i,k_j), computesT=(I+A)^-1 by ordered row recurrence, then corrected updateD=R*T^T withR=beta*(V-exp(G)*projected_old_state_on_K). Output uses causal-inclusiveF_ij=exp(G_j-G_i)*dot(k_i,q_j) andO=exp(G)*checkpoint/history projection+D*F. Each masked padding row is loaded from a valid clamped token address and multiplied by zero normalization before MMA so staging is completely defined. This is not direct recurrent state materialization and not a tree algorithm: only a linear draft chain satisfies the triangular dependencies.

At390–479, d_cache stores correctedD high part; optional rawv_cache stores either originalV for exact replay or signed D residual. k_cache stores normalized key high; rawk_cache stores either raw pre-norm key or normalized-key residual. `STORE_EXACT_RAW` versus compactD/K modes cannot share a replay arithmetic premise. FP32 checkpoint path retains FP32/TF32 operands; narrow checkpoint path includes key-residual products. The intra-window KK expansion includes high*high, high*low, low*high and low*low when enabled. Existing two-component rules that deliberately omit low*low would describe a different computation. DOT_PRECISION is a compiled numerical choice, not a target-independent exactness claim.

`lagged_state_log_materialization@1` binds this logical representation; source maximum log capacity must be power-of-two to replace modulo by `& (capacity-1)`. The code's early-flush policy reserves the whole next speculative window, including positions the sampler may eventually reject. A rejected suffix output cannot be left uninitialized on the assumption it will be rejected.

## Capacity, folds and tracking

At640–770 the compact fold loads every retained corrected update/key/gate, forms decay prefix sums and materializesS=exp(sumg)*S0+K^T*weightedD, reconstructing high/low components. Optional track count=n_history-n_accepted+track_step+1 selects the original accepted after-token boundary. Track destination is separate and does not advance the active state. Exact-raw mode instead runs the original transition recurrence with raw values/keys and beta. These have separate native error contracts.

At785–810 `_finish_gdn_replayssm_circular_fold_kernel` updates circular base by old retained count and resets write_pos/flush only for valid folded rows; this separate finish launch must follow all layer/shard state writes. At830–883 cursor advance commits exactly num_accepted and chooses the next flush flag from(new_wp+2*MAX_SPEC_LEN)>MAX_CACHE_LEN (strict >), or every nonempty commit in immediate mode. Source configuration requirescapacity>=2*max_spec_len. Caller/order contract must ensure no verify reads stale checkpoint with a reset log; the mathematical log identity alone cannot establish publication.

The immediate frozen-window rule is reusable for fold-every-commit. Circular checkpoint lag is not represented by its `pre_prefix` assumption that every commit starts from that window's original current checkpoint; the new log representation records the missing state/cursor object. Exact-rational checks/lagged_log.json validates expansion for accepted counts0..3 and distinguishes the rejected suffix, leaving native precision and ordering open.
