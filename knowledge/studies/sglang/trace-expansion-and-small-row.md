## Completed lower-body follow-up

mHC `mhc_pre_big_fuse_tilelang` at473–599 owns one token per96-thread CTA. Sum16 (default) dot and squared-norm partial planes, derive one inverse RMS from the complete HC*H axis, and publish the24-element mix vector through shared memory for HC4. Threads0–31 produce post gates and the4x4 Sinkhorn matrix; the remaining64 threads form pre gates and stream residual blocks. `hidden_block=gcd(512,H)` divides H exactly. Two-stage pipelining applies only to hidden blocks; Sinkhorn state stays local. This is a fork after shared mix readiness, not warp_specialization@1's asynchronous producer/MMA consumer stage loop. Role partition must therefore remain a source-specific realization constraint rather than a false binding of producer_warps/consumer_groups. The two output branches have no dependency after the mix vector. `iterative_state_residency@1` explains repeated register-resident Sinkhorn state; operator_fusion@2's closed fused_ops menu does not directly encode Sinkhorn, so no unconditional fusion rule binding is asserted.

IPM `jit/csrc/lplb/ipm.cuh`: `ipm_smem` holds A[NC,NV],b[NC],c[NV],Ax²[NC,NV],Ax²Aᵀ[NC,NC],x[NV],Ax²c[NC],r[NV],d[NV],alpha and availability. The source does not alias these arrays; capacity is the sum plus compiler padding. `matmul_NT/NN`:117–126 selects cuBLASDx block operations, not an audited instruction fragment mapping. Iteration176–214 forms Ax², normal equations and right-hand side, solves via lower-triangular Cholesky, projects back through A, computes d=x*(c-r), reduces max(d) within warp0, then all threads update x*=1-alpha*d. Barriers separate state transitions. Factorization56–81 clamps pivot to1e-12, distributes below-diagonal division and Schur updates across256 threads, and barriers each pivot. Forward/back substitution89–109 is thread0 serial because of carried dependencies. End216–242 computes infinity residual and writes0.5 unless d_max<0.1, final slack x[NV-1] in[0,1e-4), residual<0.05. These are actual acceptance/failure semantics, not a guarantee that the LP optimum is found. `iterative_state_residency@1 state_site=smem` and `reduction_partition@1 assignment=strided_threads` explain storage/reduction; direct cublasdx execution remains the backend boundary. The numerical solver algorithm is fixed by the caller; no optional algorithmic substitution is proposed.

Engram hash170–234 computes a complete predecessor vector for each token: shift<=offset comes from this batch, older shifts from oldest-first history, then a prefix blocked mask propagates sequence-start or image-token boundaries to every older shift. Replacing only the individual image token would corrupt longer n-grams. Token-map compression precedes per-layer multipliers; XOR-fold each prefix and apply each head prime/offset. Decode may commit reversed newest N-1 predecessors only for nonzero cache locations. Extend and verify choose different row/offset reconstruction; mode is a workload binding. Fused hash/commit must read all predecessor values before writing overlapping history. This is an instance of row ownership and local fusion; hashing multipliers/primes, overflow/modulo and blocked-prefix semantics belong to the fixed bit-exact workload. Ragged row lookup uses upper-bound to handle zero-length requests; no full hash policy is replaced by a sorting Template.

Engram gather23–101 optionally sorts request IDs and retains torch.sort's original indices as destination IDs: `address_sorted_indirect_gather@1 request_order=ascending_row_id`; unsorted uses original. `indexed_gather@1 granularity=row,index_prefetch=registers,index_reuse=1` explains indirect reads, but its case.indices_in_bounds premise applies only to the selected owned rows; sharded unowned rows deliberately produce zero and are excluded from loads. FP8 decode uses E8M0 exponent bits, with code0 explicitly2**-127 (not zero); code255 must be excluded by a finite-scale contract. Power_of_two_scale_encoding@1's normal FP32 code1..254 scope cannot certify this code0 extension. Peer variant104–145 finds owner by predecessor search in padded monotone starts, uses pre-biased peer pointer tables and canonicalizes negative zero to match sharded sum. This replaces zero-fill+allreduce only with complete disjoint shard coverage and accessible peer mappings; topology/pointer visibility remain a native obligation. Address ordering is a performance hypothesis, not measured here.

## Recurrent-state reading checkpoint

`jit/csrc/attention/kda_packed_decode.cuh`:52–151 is a distinct streaming realization, K=V128. CTA index owns one(request,value-head), maps shared q/k head as hv/(HV/H), each warp owns a contiguous V-row subset, each lane four adjacent K elements. Setup redundantly recomputes normalized q/k, per-K exp(decay), sigmoid beta for each warp; no cross-warp barrier is needed because no state row is shared. A row loads512 bytes of FP32 state, applies decay, computes t=dot(h,k), updates h+=(v-t)*beta*k, computes output dot(h,q), then stores the same row. `output_tiling@2 executor=warp,tile_m=128/kWarps,tile_n=128,index_map=custom` describes rectangular state-row ownership; `reduction_partition@1 assignment=strided_threads` and cross_lane_reduction@1 (reference package, full binding pending) describe the32-lane dots. Input-slot indices<0 produce zero outputs and no pool mutation. Distinct live slot IDs are necessary to avoid cross-request write races. FP32 recurrent arithmetic and BF16 output conversion are fixed numerical contracts; source tolerance comments are not new evidence.

`ops/attention/kda_decode_mtp.py`:45–108 and632–758 makes a different locality choice. One-token dense-grid streaming chooses a short V tile and16 K lanes; multi-token verification retains all V tiles across the token chain with8 K lanes, avoiding state reload/write per token. Two cp.async stages bound shared in-flight storage. Stage i uses i%stages; wait-group and warp synchronization precede its register reads, then slot reuse follows last copy read. Within each V pass tokens remain sequential, because next token consumes the prior updated state; independent V-row passes may repeat token setup. `iterative_state_residency@1` explains the resident token recurrence only when all dependencies for that V pass are local; it does not treat different speculative token states as independent outputs. `multi_buffer_rotation@2` and async_transfer@1 are applicable leads requiring explicit stage binding from the full body. Phase1 fuses width4 convolution, q/k normalization and gate setup; phase2 recurrence; optional output RMSNorm adds a full-V dependency and must follow every row's output. The narrow/wide block and16-vs8-lane policies are source heuristics, with source-reported timings unverified here.

`ops/attention/cutedsl_gdn_mtp_ring.py`:638–752 retains FP32 update accumulators while BF16 state is an output representation. Optional per-token scatter writes each h[t+1] to fresh pool slot provided by ssm_state_indices, mutually exclusive with dense intermediate checkpoint mode; final input/output slots may differ. ReplaySSM ring adds q/k/g/beta/value traces, with only i_v0 writing shared q/k quantities to avoid duplicates. This variant cannot inherit an in-place-only state-write claim. Full source-generation and ring commit rules remain to be read before recurrent family closure.
