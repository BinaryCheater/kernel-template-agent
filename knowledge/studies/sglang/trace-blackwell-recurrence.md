# Blackwell recurrence variants

Source prefix: python/sglang/kernels/ops/attention/linear/. NVIDIA SM100, K=V128 and BT64 are source realization constraints. These are materially different from the CUDA piece-map prefill route.

## Four-stage factor/state/output pipeline

`kda_blackwell/__init__.py`:1–17 orders Triton prologue → KKT/inverse/UW → sequential H → parallel O. `prologue.py`:20–75 computes per-feature cumulative gates and endpoint frames, emitting BF16kL=k*exp(gcum-glast),kR=k*exp(glast-gcum),kg=k*exp(gcum),qg=scale*q*exp(gcum),qg2=scale*q*exp(gcum-glast), plus FP32gcu. These products recover feature-dependent exp(g_i-g_j) inside KKT; a scalar post-dot gate multiplier would be wrong. kL/qg2 may grow while their paired factors shrink; finite representable operands and masks are numerical premises. Ragged masked rows contribute zero to glast, so endpoint is the last real token.

`kda_blackwell/kernel_kkt_inv_uw.py`:1–18 then usesKKT=kL*kR^T, strictLower(beta*KKT), inverse(I+A), U=(inverse*beta)*V and W=(inverse*beta)*kg. Gate folding in the prologue is the distinct algebraic choice: row_column_rescaling@1 cannot represent an arbitrary feature-dependent exponential outside a contraction, so that rule is not an unconditional binding. The inverse diagonal16x16 blocks are computed by three Newton-Schulz polynomial doublings407–462, captured in nilpotent_inverse_doubling@1. Off-diagonal assembly follows the four-block unit-lower inverse contract; bind blocked_unit_lower_inverse@1 block_order16,p.order64 with the new diagonal inverse realization and its separate BF16 error policy. This avoids mistaking diagonal inversion for scalar row substitution.

The source uses persistent chunk/head tiles with warp9 TMA supply/store, warp8 tcgen05 issue and the remaining four-warp compute group doing inverse/readout. Every stage waits for matching TMA/MMA completion before reading or overwriting. The old warp_specialization@1 template hardcodes a producer-load loop and consumer MMA groups; it does not directly encode this issue/readout role graph. Role counts and edges are retained as this realization's fixed mapping; reusable general role-graph abstraction remains a candidate gap, not an invented producer_warps binding.

`gdn_blackwell/kernel_h.py`:312–343 issues two contractions per chunk: corrected value=U-W*old_state, then new_state=decayed_state+correctedV^T*K. At354–471 H warps supply a BF16 old-state view for the first contraction, separately retain/scale an FP32 state view for the update, and publish each readiness. At540–625 V warps loadU, wait first MMA, cast correctedV to BF16 and publish it for the second MMA/output. Final state uses original caller slot index and stride, and saved incoming state goes to the O kernel. KDA sibling applies per-feature gate scaling through precomputed framed operands instead of the scalar-GDN last-gate multiplier; neither may overwrite the old-state projection view before its first contraction completes. `iterative_state_residency@1 state_site=smem` applies only to the shared working state; actual tcgen05 accumulator residence is TMEM, outside that candidate's two-site domain and therefore a realization extension still to represent. `physical_storage@1 level=tmem` describes that residence with its last-read/write lifetime, while compute_instruction_selection@2 selects the concrete contraction backend. No proof of native fragment correspondence is inherited.

## Persistent fused chunk consumer

Output store code902–945 waits for readout full, writes a TMA tile, commits and waits for shared-memory source reads before releasing the slot. A stage-count1 declaration alone is not sufficient arrival evidence.

The twelve-warp source graph dedicates issue/TMA work in WG0, state conversion/decay inWG1, and W/NV/O readout inWG2. It is not semantically the same role loop as warp_specialization@1, although per-channel generation/completion primitives reuse per_slot_handshake@1. Persistent scheduler assigns independent sequence/head state chains; within each chain chunks remain ordered.
