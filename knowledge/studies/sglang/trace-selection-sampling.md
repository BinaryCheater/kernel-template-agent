## Cluster DeepSelect is a distinct schedule

`jit/csrc/deep_select/vendor/cuda_kernels/v3_cluster/topk_select.cuh:27-167,220-255,277-443,510-588,600-914` supplies the device body. Config fixes occupancy1,512 threads,MAX_TOPK512/1024 and cluster size2/3/4/8/16. Slices are contiguous and64-aligned, and the partial tail stage is visited in the initial window. Each CTA's32768-value initial window gives the cluster a conservative global kth pivot. Short slices select directly from the complete window; long slices retain initial winning records and later values strictly above the conservative threshold.

Every CTA pushes its256-bin histogram to every other CTA. Counts are packed as unsigned16-bit bins; initial local windows are bounded32768 and later local candidate sets4096. MSB exchange is132 words per sender (including NaN flag); LSB128 words. Per-recipient transaction barriers expect cluster_size*132*4 and cluster_size*128*4 bytes, respectively. Transfers use16-byte `st.async.shared::cluster.mbarrier::complete_tx::bytes.v4.b32`; acquire-cluster waits establish visibility. Reuse `async_transfer@1` with granularity16 and barrier-wait completion plus physical storage/replication for the histogram mailboxes; numerical radix selection uses `radix_threshold_selection@2` key_bits16,digit_bits8. Zero is canonicalized before both histogram and value comparisons.

Candidate overflow does not silently clip: a whole batch attempts warp-prefix reservations; if any fail, the CTA rewinds every reservation from that batch after synchronization and retries stage by stage. A failed stage is included directly from the still-resident ring along with the old candidates in an exact local reduction to k. This advances the threshold only after k local witnesses exist. The ring is not refilled until these retries finish. Stage8192 plus candidate4096 therefore has a complete logical compaction input even though candidate storage alone is4096. Four stages are processed per batch; ring depth is derived from a225KiB budget and must exceed the four-stage initial window. Separate cluster-wide final histograms choose the global pivot; CTA0's cursor grants output slots, or sorted-index mode uses lower-CTA counts and local prefixes.

This is a conservative global-witness bootstrap followed by capacity-triggered local compaction and global final selection. It is not a literal binding of the single-worker `streaming_topk_filter@2` schedule: before local compaction a CTA need not hold k records, and overflow rollback is a distinct storage protocol. The common rank invariant is k witnesses somewhere in the cluster before discarding at the bootstrap threshold, then k local witnesses before raising a local threshold. The independent rank and storage choices are now proposed as `witness_bootstrapped_sharded_topk@1` and `reservation_rollback_retry@1`; concrete bindings and checks follow below.

## Block verification: resident prefix recurrence and guarded mass refinement

`ops/speculative/reject_sampling.py:45-132` fixes this mode through `BLOCK_VERIFICATION`; it is a distinct workload algorithm rather than an interchangeable implementation of classic per-token acceptance. The source references [Block Verification, Algorithm2](https://arxiv.org/html/2403.10444v3). The important kernel choice extracted here is work skipping, not a new sampling-law proof.

For draft length L=NUM_SLOTS-1, the source computes c_0=1 and c_i=min(c_(i-1)*P_(i-1)[draft_i]/Q_(i-1)[draft_i],1), rejecting invalid q. It retains all c_i in a static register tuple, then searches i=L..1 for the longest passing prefix. The final prefix uses threshold c_L directly. For an interior prefix with0<c_i<1, compute M_i=sum_v(max(c_i*P_i[v]-Q_i[v],0)) and test the same coin against h_i=M_i/(M_i+1-c_i). Accepted prefix i uses scaled correction max(c_i*P_i-Q_i,0); i=0 starts with scale1. All accepted uses the target bonus row.

The source first tests coin<c_i. Since normalized P gives M_i<=c_i, the interior h_i<=c_i; a failed cheap comparison can skip the vocabulary reduction exactly under ordered conservative arithmetic. Proposed `upper_bound_guarded_refinement@1`, evaluation=guarded, cheap_upper_bound=c_i, exact_threshold=h_i captures that independent choice. Exact rational normalized two-token rows validate this bound in `checks/lazy_threshold.json`; native FP32 sum/ratio conservativeness remains a numerical premise. The same coin is reused, so guarded execution consumes no extra random value.

`physical_storage@1`, level=reg,buffer=dedicated,share_order=none binds c_i's tuple occupancy from its forward write until the reverse search reads it; p.size_bytes=4*L for logical FP32 prefix scalars (compiler replication is separate). Vocabulary reductions use `BLOCK_REDUCE=min(next_power_of_2(V),32768)`, four warps except eight when block verification and block_reduce>4096; correction CDF tiles remain4096. Reusing already computed M_i as the correction normalizer avoids a second mass pass at the selected prefix. This does not remove the final CDF scan. Probability provenance, independent coins, matching histories and finite endpoint/zero-mass policy remain inputs to this algorithm; the work-skipping rule alone does not certify them.

## Paired cluster choices and replay

`witness_bootstrapped_sharded_topk@1` binds workers=2/3/4/8/16,bootstrap_per_worker=32768. Bootstrap winners carry a global k-witness certificate even on CTAs holding fewer than k records; after an overflow-triggered exact local compaction, a CTA has k local witnesses and may safely raise its threshold. Final histogram selection includes every CTA's retained candidates. The proof does not substitute a locally undefined kth rank for the initial global pivot.

`reservation_rollback_retry@1` binds batch_stages=4 with candidate capacity4096 and stage8192. Range reservations can temporarily exceed capacity, but writes are guarded per thread and do not touch the old committed prefix. A collective barrier precedes subtraction of all batch claims. Successful speculative suffix writes become dead after rewind; the unchanged ring supplies exact retry input. `reduce_candidates` loads eight old records per thread plus sixteen stage values into registers, with a census barrier before any candidate overwrite. This is a physical-lifetime choice separate from rank selection.

`checks/sharded_selection.py` / `.json` replays exact three-valued rows through length8, two/three worker shards, global bootstrap, local threshold raises, ties and stage compaction; all tested final value multisets equal full-row top-k. Separate claim-order replay covers every ordering of three claimants and counts0..3 across capacities2..8, proving restoration of the committed counter and unchanged prefix in that host model. Native memory ordering and progress remain the paired protocol obligation.
