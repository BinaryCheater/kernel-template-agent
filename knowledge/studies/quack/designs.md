## Hadamard mechanism boundary

transform/hadamard.py:78–114 assigns logical bits to thread or register coordinates; plan381–438 groups up to log2(ept) butterfly bits per stage and rotates ownership through shared memory. kernel performs local Hadamard then row-local shared exchange; final TailDirectStorePlan can skip restoring original owner layout by constructing the store mapping from the remaining ownership permutation. Example N2048,ept64,vec8 starts thread bits(3,4,5,6,7), value bits(0,1,2,8,9,10). Persistent dispatch is only N32768 with16-bit types and assumed occupancy1; it is a measured menu in source, not generic proof.

Existing butterfly_linear_transform@1 H<=512 cannot cover the full library menu. This is a proposed domain/realization extension, recorded in delta/butterfly-bit-ownership.md with its invariant and proof outline. Small supported normalized power-of-two instances bind H,V and threads; this source instead exposes arbitrary scale and zero-pad-to-next-power2 then crop. The padded transform/crop is part of the workload, not a numerically neutral optimization of an unpadded nonpower2 transform.

## Remaining numerical and representation designs

- rounding.py:251–294: random_discarded_bit_rounding@1, discarded_bits16. Software BF16 perturbs low discarded bits then converts toward zero, while hardware path174–179 consumes the same packed random word. Seed at115–128 depends on tile M/N/batch/subtile: changing tiling does not preserve element RNG automatically. FP16/FP8 variants use scaled-grid FMA before narrowing; FP4 at727–750 prescales by2^-14 so E2M1 subnormal knee1 aligns with FP16 knee2^-14 and extracts magnitude bits14:9, clamped7. This is a concrete grid-embedding realization, with separate numeric obligation; it is not BF16 truncation with a renamed destination.
- operand_transform/formats/__init__.py:151–238: Int4 group32/64/128 unsigned offset-binary codes bind groupwise_affine_quantization@1 group_size32/64/128,code_bits4,zero_point=integer. AWQ adds per-group zero point through packed bias and scale. Group32 selects strip word by k16 block; groups>=64 duplicate shared scale across tiles. Every scale covers the same logical K interval as its decoded fragment.
- formats/__init__.py:242–317: sign-magnitude int4sm decodes exactly into E4M3 then promotes per128 K; block_scaled_partial_accumulation@1 partial_k128,gran_k_a128,gran_k_b=fullK (token activation scale outside),gran_m1,gran_n1. Fold variant instead builds scaled magnitude LUT each tile, rounding each scaled weight to E4M3 and avoiding promote. This changes the quantized numeric representation and requires a new error admission; it is not a legal exact hoist of arbitrary scales.
- formats/__init__.py:333–372: experimental biased int4b8 maps q+8 to E4M3 subnormals2^-9. Promote scale multiplies512; mathematical correction is -8*sum_group(scale*sum(activation_group)), a group-rank contraction rather than one vector scale. Source roundtrip=False explicitly excludes treating raw GEMM result as corrected output; comments' observed fast-accumulator error remains an upstream finding, not a measurement here.
- complex.py:38–118: a complex64 value occupies f64 ABI storage with real bits low32 and imaginary high32; bitcast/unpack compute Float32 components. This is physical_storage@1 level=reg or gmem,buffer=dedicated,share_order=none with an explicit representation realization, not numerical Float64 conversion. Operator promotion must dispatch to Complex64 before real Float64 conversion. No complex GEMM entry is inferred just because the value type exists.
- rms_final_reduce.py:87–118: row_reduce sums already formed squared-norm partials, then rsqrt(sum*scale+eps) once. reduction_partition@1 assignment=strided_threads; padding partials initialize0. It must not square the partials again. This closes the norm epilogue/finalizer interface.

## Irregular-descriptor and empty-participant contracts

copy_utils.py:423–518 concretely implements ragged_descriptor_rebase@1: B2^30, complementary stride2^34-s and modulo64-bit address cancellation. varlen_utils.py:120–154 selects no-pointer-shift load form for ragged M and rank-dependent form for K;169–202 aligns scale storage to128-element atoms at floor(cu_seqlen/128)+batch, independent from payload sequence offset. Prefix counts for variable-M scheduling are now extracted as lookahead_prefix_group_decode@1, not falsely claimed as the32-count-input realization of online_group_work_decode@2.

The split-K empty-range behavior at tile_scheduler.py:637–657 is captured by reduction_partition@2 range_policy=balanced_quotient, group_size=ceil(Ktiles/splits). Migration from seed@1: all existing fields preserved, range_policy=uniform; no-empty bindings retain original mapping. New empty splits require identity publication plus arrival even though no compute work is issued. This is why source emits zero epilogue/turnstile rather than early-returning an empty participant.

FP4 carrier-grid extraction is now recorded as aligned_low_float_grid@1; its16-bit carrier binding is separate from random_discarded_bit_rounding@1. This retains the source choice without claiming BF16 bit-truncation proof covers FP4 subnormals.

bitstream_packing@2 migration: old code_bits/word_bits fields retained, word_bits domain8/32; old length%32 guards imply complete containers. QuACK FP4 uses2 codes/byte and FP6 uses4 codes/3 bytes. New bit-identity outline preserves existing ownership obligations and does not assume arbitrary concurrent OR writes are safe.
