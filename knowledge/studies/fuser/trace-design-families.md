# Additional Fuser design families

Representative-design pass reconciled. All locations are relative to the retained Fuser revision. This page supersedes possible-match rows in the initial inventory as each representative is resolved.

## Persistent values: retain versus rematerialize

csrc/scheduler/normalization_utils.cpp:845-933 chooses whether to preserve a computed tensor across a reduction or preserve its projectable inputs and regenerate it. Projected size must be positive, view ops are excluded, and projected storage is normally smaller. The source considers capacity first, then RNG and exponential recomputation costs; the early capacity-forced branch precedes the RNG test, so a universal “source always rejects RNG” statement would be incorrect. The Template below admits only pure deterministic producer slices, independently of the source policy order.

Binding: a FP16 row x feeds FP32 v=cast(x)*a+b used before and after row statistics. Retain x (2N bytes) and scalar a,b instead of v (4N bytes), then repeat the exact cast/multiply/add DAG after statistics. New persistent_value_rematerialization@1 explicitly selects the retained frontier. It is broader than affine_activation_rematerialization@1's specific activation checkpoint contract, but narrower than unrestricted compiler recomputation: RNG, mutation and unpaired numeric reordering are excluded.

normalization_utils.cpp:1380-1433 supplies a second binding: retain one shared-memory value, generate a separate register-cache load per consumer. physical_storage@1 level=smem holds the persistent frontier; register copies are short-lived. With TMA warp specialization plus circular register caching, the code keeps the shared→register edge singular so the producer may refill after register capture instead of after all later math. This changes the last reader of shared storage, not the last user of the logical value.

## Pointwise vectorization and broadcast reuse

csrc/scheduler/pointwise_non_tma.cpp:30-86 distinguishes outer-broadcast inputs from other inputs: values broadcast across outer unrolled iterations are loaded once and reused. :90-137 derives empirical unroll from bytes needed in flight, vector width, computation cost and non-broadcast input count; :140-183 forces unroll=1 for block quantization because its runtime has a fixed grouping contract. These are policy choices constrained by available vectorization and actual grouping, not semantic claims that larger unroll is always faster.

Concrete output_tiling@2 binding: thread executor, tile_m=4,tile_n=1 for four independent outer points; a broadcast scalar is one physical_storage@1 register occupancy spanning all four uses, while distinct elementwise inputs have four separate values. Changing unroll cannot merge or shift quantizer scale groups. The bytes-in-flight rule is a source heuristic, not measured evidence in this study.

## Transpose at a change in thread ownership

csrc/scheduler/transpose_non_tma.cpp:248-271 derives elements_per_thread=tile1*tile2/threads, then decomposes it into vectorize*unroll independently for the two tensor groups. :457-494 inserts shared caches at the boundary between incompatible innermost-axis groups. :627-633 explicitly permits the thread-binding swap anywhere on the path; cached inputs/outputs are the chosen placement.

Concrete instance: 32×32 tile, 256 threads, four elements/thread. Group 1 may choose vectorize=4,unroll=1 and group 2 vectorize=2,unroll=2; both cover 1024 points. output_tiling@2 supplies the tile; thread_ownership_exchange@1 supplies cooperative load→shared→consumer ownership; physical_storage@1 lifetime requires the shared tile survive the last differently bound reader. tensor_axis_permutation@1 is NOT reused: it is rank-three metadata-only view transformation and does not express this materialized ownership exchange. exchange_boundary=cached_input or cached_output explicitly records placement. shared_memory_tiling@1 is GEMM-specific and is not a valid transpose binding.

## Fused tuple reductions and double-bank retirement

runtime/fused_reduction.cu:14-83 applies independent functions componentwise to tuples; this is a product reduction, unlike Welford which couples count/mean/M2. :455-488 defines parallel dimensions as reduction/iteration/collapsed and requires persistent mode for broadcast. :1210-1249 broadcasts results locally and explains why two global banks remove the extra retirement grid join.

Concrete binding: two tuple fields (sum,max), same input partition; reduction_partition@1 applied once per component, with identity (0,-infinity). physical_storage@1 supplies two shared global banks. At generation t, store/read bank t%2; before any producer overwrites that bank at t+2 it must cross the t+1 publication rendezvous. Every participant enters t+1 only after its t reads, so that intervening rendezvous retires bank t. This is the lifetime argument required by physical_storage@1; no claim that the CTA-only multi_buffer_rotation@2 proof establishes this grid protocol. The earlier designated_segment_completion@1 applies only to the single-bank representative; fused ping-pong is a separate chain binding, not that rule's second-join mode. TransformerEngine reusable_group_partial_allreduce@1 supplies the same retirement insight but its two-counter/four-phase state machine is not copied onto Fuser's single phase-flipping semaphore.

## Quantization value and scale ownership

runtime/block_quantization_kernels.cu:64-82 reduces absmax by XOR across adjacent subwarp groups; :149-185 MXFP8 binds group_size=32, ITEMS_PER_THREAD=4 → eight threads/group. Exactly threadIdx.x%8==0 stores scale logical_index//32. :202-267 NVFP4 binds group_size=16, ITEMS_PER_THREAD=4 → four threads/group; encode s=E4M3((amax/6)*S), decode s to FP32 before computing min(1/(s/S),FP32_max), then encode E2M1(x*multiplier). Without global scale S=1. This exact scale-before-code order binds groupwise_low_float_quantization@1 format=nvfp4,group_size=16 in the no-global, positive finite regime. Global-scale mode binds hierarchical_low_float_scaling@1 group_shape=vector16,outer_domain=tensor when caller S=2688/outer_amax and its finite premises hold. Supplied arbitrary S remains an explicit applicability extension; the source accepts it but the old rule's amax-derived scale premise must not be discarded. MXFP8 helper uses __float2e8m0; native conversion rounding is an obligation before claiming identical CUTLASS upward rounding, not inferred from the type name.

Scale layout at :290-315 splits row m into (m//128,(m%128)//32,m%32) and scale-column k into (k//4,k%4); stores in [m//128,k//4,m%32,(m%128)//32,k%4] order. Example (m,k)=(33,5) has digits (0,1,1,1,1), while (32,5) differs only in m%32; a logical row is not contiguous metadata. :16-58 has another tile-digit layout with row_outer=row%R_outer and row_inner=(row%R_tile)//R_outer. Both bind blocked_scale_digit_layout@1; the NVFP4 path uses R_outer=32,R_inner=4,C=4. tensor_axis_permutation@1 cannot bind split rank-five digits.

## Communication paths

runtime/alltoallv.cu:9-38 assigns peer=blockIdx.y and byte index=blockIdx.x*blockDim.x+threadIdx.x. Byte count is send_sizes[peer]*elem_size; source offset send_offsets[peer]*elem_size, destination remote recv_ptrs[peer]+recv_offsets[peer]*elem_size. output_tiling@2 executor=thread,tile_m=1,tile_n=1,index_map=custom binds the independent destination bytes. Precondition: peer ranges are disjoint, remote pointers are accessible and stay live, and upstream ordering establishes writes before observation. No atomic combine is present: routing two source ranges to one destination is illegal unless separately ordered.

runtime/multicast_reduce.cu:9-42 is a different design: SM90+/PTX8 multimem load-reduce over a multicast address, four FP32 elements per 16-byte vector and a grid-stride loop. compute_instruction_selection@2 does not bind this engine: its domain is contraction instructions, so multicast reduction needs a separate rule. output_tiling@2 partitions independent output vectors; reduction peers remain inside the load-reduce operation. The device instruction performs peer reduction, whereas the ordinary alltoall kernel performs byte copies. Input rank readiness and multicast membership are caller obligations; n_bytes must cover whole 16-byte vectors in this body. No scalar residue is implemented here.

runtime/grid_broadcast.cu:62-91 uses one designated last-coordinate source and two joins, first for visible publication, second for all readers to retire. physical_storage@1 supplies the lifetime; output_tiling@2 maps surviving dimensions. It is a one-source broadcast, not a sum of CTA partials. Cluster primitives in runtime/cluster.cu:12-126 distinguish relaxed arrive (no prior-memory ordering), ordered arrive/wait and asynchronous remote stores with receiver mbarrier byte completion; selected cluster callers still need separate tracing.

## Outer Welford reduce-scatter

runtime/block_welford_outer.cu:11-58,:105-195 is materially different from the ordinary block tree. Bind butterfly_reduce_scatter_chunks@1 lanes=32/BDIMX,values=NumVals; BDIMX=8,BDIMY=32,NumVals=8 gives 8 warps, four reduction lanes per column and two final components/lane. Recursive halves combine Welford triplets via centered_moment_merge@1; shared mean/variance payload is reduced by factor four before cross-warp combining. The shared layout stores [chunk,wid,(warp_tidy+wid)%4,TIDx], a cyclic row swizzle. cyclic_warp_row_skew@1 binds row_width=8,warp_skew=1 with inverse warp_tidy=(stored_digit-wid)%4. The XOR-only choice in shared_resource_binding@1 does not capture this modular-add mapping. Count is uploaded once per warp, relying on shared count across all grouped values, not eight unrelated sample cardinalities.

## Hopper/Blackwell matmul scheduling

csrc/scheduler/matmul_hopper+.cpp:177-212 orders operand caching, role rediscovery, prologues, cluster tiling, MMA allocation, epilogue and circular buffering. :220-290 factors both M and N traversal axes into outer sections and intra-section digits: concrete factors (2,4) traverse 2×4 tile sections. This is a two-axis extension of block_rasterization@1, whose grouped_m/interleaved_n menu does not name arbitrary rectangular sections; no silent choice of its order field is made.

:702-704 applies TMA shared swizzle. :746-764 uses Tensor memory for Blackwell MMA output (currently M128 macros) but register-fragment allocation for Hopper. compute_instruction_selection@2 binds instruction=tcgen05_mma versus wgmma_m64nNk16_f16,operand_source=ss,accum_dtype=f32; physical_storage@1 level=tmem versus reg owns accumulators. :768-782 requires CTA tile dimensions divisible by the instruction tile. :810-814 applies split-K rFactor when splitk_factor>1; :1276-1318 requests serial grid reduction at BIDz for the combine, with Blackwell TMem loads separately vectorized. reduction_partition@1 assignment=contiguous_parallel creates those partials; serial combine order is a numerical/visibility binding, not an atomic reduction claim.

:1350-1381 chooses pipelined versus warp-specialized circular buffering. Register sharing is enabled only for exactly two math warpgroups; otherwise omitted because the one-math/one-DMA group CTA cannot exceed the per-thread register limit usefully. :1386-1427 requires stages>1 and positive gap<=stages, derives prefetch=stages-gap and requires async loading for stages>2. async_transfer@1 selects the transfer mechanism and physical_storage@1 supplies slots; actual warp-specialized barriers are outside multi_buffer_rotation@2's CTA-barrier proof. The source pipeline's free knobs are stages/gap/role partition; prefetch is derived, not another independent knob.

## Resize and graph scheduling

csrc/scheduler/resize.cpp:70-112 excludes reductions/resharding/sub-byte values, :397-411 clones a shared producer for a nonexclusive resize consumer before rewriting its domain; :438-447 pushes resize operations to inputs only in a pointwise graph. pointwise_slice_demand_pushdown@1 binds the slice-demand rewrite; operator_fusion@2 lacks that field and is not used as a substitute. boundary_predication@1 handles the separate padding-output guard. A concrete slice y[j]=F(x[j+L]),0<=j<N-L avoids evaluating discarded F outputs; a padded region must preserve the pad constant rather than apply F to it. Nonexclusive consumers require separate producer copies so the unsliced consumer retains its original domain. Full resize-through-pointwise legality therefore requires preserving each operation's padding semantics; it is not claimed for arbitrary reductions.

Greedy graph grouping and copy insertion are traced in the completed follow-through below.

## Completed Greedy / cluster follow-through

csrc/scheduler/greedy.cpp:166-170 identifies argsort,pad,scan,scatter,top-k as constrained operations. :1016-1070 inserts exclusive copies between constrained or multiply-used values and keeps constrained outputs in their required storage. :1341-1445 groups argsort/scan inputs with output and propagates an initial constrained reference forward/backward without overwriting an existing group. :1670-1720 materializes shared copies only for consumers whose thread mappings conflict. thread_ownership_exchange@1 exchange_boundary=cached_output binds these conflict edges when the actual producer/consumer maps satisfy its tile premises; physical_storage@1 level=smem/gmem is selected by :1166-1185 for scatter inputs/outputs. A scan followed by argsort therefore need not force both operations into one thread ownership map. The source heuristic uses first-reached references, not an optimal graph partition claim.

runtime/cluster.cu:140-319 and tests/cpp/cluster_runtime_test/cluster_test_kernels.cu:46-112 supply a concrete SM90 cluster caller beyond wrappers. cluster_partial_destination_table@1 binds peers=2,warps=4,scalar_bytes=4 and destinations=last_cta versus all_ctas. Each destination expects 2*4*4=32 bytes. Source slot rank*4+warp identifies each sender; elected lane root delivery differs from lane-selected all-rank delivery. The separate ring-exchange test writes to peer=(rank+1)%CLUSTER_SIZE and waits on receiver-local expected BLOCK_SIZE*sizeof(T). Barrier initialization is cluster-published before remote stores. Caller exit/retirement still requires its native obligation; the observed one-shot phase-zero code is not promoted to a reusable barrier.

csrc/scheduler/matmul.cpp:68-88 explicitly rejects Turing/Ampere scheduling at this revision and selects Hopper versus Blackwell implementations. Old architecture code is not a further active kernel family requiring audit.

csrc/multidevice/cuda_p2p.cpp:830-960 establishes the multimem allreduce caller: SUM/FP32/16-byte multiples only; copy input into rank-local symmetric storage, publish InProgress to peers through stream memory operations, wait all peers ready, run load-reduce, publish Idle after completion, and wait peer Idle before handle reuse. This supplies the missing publication/retirement boundary of runtime/multicast_reduce.cu. Root-only reduce uses the same arithmetic body with a single consuming rank. A multicast address denotes one corresponding element in every member allocation; it is distinct from CTA-cluster shared multicast and must not reuse cluster_multicast@1's CTA scope.

The supplied-scale, sectioned traversal and multimem proposals are resolved below. All other inventory registrations now have a representative implementation or explicit inactive/delegated disposition.
