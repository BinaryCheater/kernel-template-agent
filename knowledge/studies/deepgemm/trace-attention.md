# MQA logits: dense, paged and sparse

Source paths are relative to the retained DeepGEMM revision in [sources.json](inputs/sources.json). This group includes every attention API registration, both SM90 device bodies, the shared SM100 dense/paged body, the shared SM100 sparse body and all four metadata schedulers. Analysis is CUDA source substitution on SM90a/SM100f. The API computes weighted ReLU dot-product logits; it does not perform a softmax or a value contraction.

## Contracts and one concrete value path

The logical result for Q row q and KV position k is `sum_h weight[q, h]*ReLU(dot(Q[q, h,:], KV[k,:]))` after the input representation is decoded. The source tests use that expression as reference (`tests/test_attention.py:78–101`). For dense KV, each row declares `[ks, ke)` and writes compressed output column `k-ks`; allocation capacity and unwritten tails are not part of the result. With starts `[5,2,8]` and ends `[9,7,8]`, the required columns are respectively `[0..3]`, `[0..4]` and none. A common Q-block span starts at floor(min(ks)/4)*4 and spans through max(ke), while the per-row stores select valid positions. Require ordered, valid bounds: dense span arithmetic clamps each endpoint to the KV tensor but does not repair reversed intervals.

SM90 uses FP8 Q/KV, one positive FP32 quantization scale per KV token, FP32 weights and logits, heads32/64, head_dim32/64/128. Its raw dot is followed by ReLU and weighted head partials, then a KV scale and four-lane shuffle sum (`impls/sm90_fp8_mqa_logits.cuh:280–315`; paged counterpart`:296–329`). Moving a shared scale through ReLU needs it to be nonnegative. [nonnegative_scale_hoisting@1](delta/nonnegative_scale_hoisting@1/template.yaml) makes that premise and the rounding contract explicit. A negative KV scale can pass the public dtype checks but violates this mathematical interpretation; the scalar counterexample is score-1, scale-2. Quantization helpers use positive magnitude-derived scales; arbitrary API scale tensors need their own contract.

SM100 uses packed int32 UE8M0 SF for both Q and KV, FP8 or packed FP4 data, BF16 weights and outputs. Its scaled UMMA dot accumulates in FP32, then each ReLU score is rounded to BF16 before BF16x2 weighted FMA accumulations. It maintains two pair streams over groups of four heads, combines the pair streams and then the two halves. This is not an FP32 head sum followed only by a final cast. The bounded witness scores1 and weights `[256,1,-256,1,1,1,1,1]` produces5 under those source-shaped BF16 operations versus exact sum6. This distinguishes evaluation orders; it does not establish or reject an end-to-end tolerance. The source API accepts heads divisible4 up to128; BLOCK_Q=floor(128/heads), UMMA_N=align(BLOCK_Q*heads,8). Non-divisors need not fill128 rows, despite the host comment's shorthand. Sparse kernels restrict heads to at most32.

## Dense metadata and persistent ownership

The SM100 dense runtime fixes SPLIT_KV384, three math warpgroups/tensor-memory stages, Q stages3/2 and KV stages3/8 for FP8/FP4 respectively (`csrc/jit_kernels/impls/sm100_mqa_logits.hpp:11–146`). Q groups either stride by num_sms without metadata or read per-SM metadata. Each Q block's aligned cover is divided into KV splits. Metadata builds work and estimated-cost prefixes with cost `2*splits + (splits?3:0)`, then locates monotone per-SM boundaries in cost order. Startup cost3 versus split cost2 is a heuristic, not a legality constraint or measured KTA number.

A per-SM record stores `(Q block, split offset)`, a split count, and spans placed after an eight-byte-aligned word offset. Scheduled consumers can start/end inside a Q block. Empty blocks are skipped; repeated boundaries create idle SMs. The scalar replay recovers the full independent `(Q block, split)` enumeration for1280 domains, including zero work and more SMs than splits. The host bounds both total work and cost to uint32 and shared memory before launch. Reusing metadata requires the same bounds, head-derived block_q and num_sms; its physical shape alone does not prove that provenance.

## Paged storage and scheduling

A cache tensor's nominal shape is `[pages, page_kv,1, token_bytes+4]`, but **the bytes within each page are split into two arrays**: all `page_kv*token_bytes` KV bytes, then all `page_kv*4` SF bytes. `csrc/apis/attention.hpp:213–229` constructs KV and SF views with different bases/strides. The test constructors confirm that order (`tests/test_attention.py:256–282`). The scaling-format document §6.1 describes per-token trailing SF bytes; that wording does not match these views. The address witness crosses logical tokens63→64 through a nontrivial page table and rejects token-interleaved addressing.

SM100 supports page sizes32/64/128 and varlen request rows with next_n1. Consecutive equal `indices` define a request; the last query's context is assumed longest and paired rows must refer to compatible block tables. Metadata uses a fixed Q block4 to estimate cost (tuned for heads32), while execution derives its Q grouping from the actual head count. That estimate changes balance without changing request split ownership. Request split counts are ceil(last_context/384). Cost is `splits*(2*4*ceil(tokens/4)+tokens)`; overflow triggers the source's token-cost recomputation. Further overflow and cache-table validity remain input/validation obligations, not performance findings.

The scheduler distributes a request's queries evenly over Q blocks, then visits each KV chunk across those Q blocks. Example: ten queries and block_q4 give query-group sizes4,3,3. For nine KV splits and chunk bound8, it emits three Q groups for splits0..7, then three for split8. Per-SM boundaries cut at request split positions, not individual queries. The cache for page coordinates holds32 pages per lane bundle; out-of-range pages use physical page0 as a safe speculative source and must be excluded by the final context predicate. Physical page indices must reference allocated pages.

KV/SF data may remain resident across consecutive query groups of the same chunk. Source reuse requires `kv_shared_with_prev` **and** `num_kv_splits==num_kv_stages`. Exactly one full ring traversal preserves chunk-to-slot identity. Replaying counts1..2S for S3/8 recovers this guard; an arbitrary shared chunk length does not. Reused SF must not be transposed a second time. This is a source instance of storage lifetime and resident-value identity, with a conditional reload/reuse edge left in the family binding.

SM90 paged supports page64, FP8, heads32/64 and next_n1/2. The API's broader next_n>=1 check is narrowed by the runtime (`sm90_fp8_mqa_logits.hpp:192`). Metadata divides 256-token splits with reversed remainder allocation so idle SMs normally start inside the first productive request. The scheduler constructor nevertheless refreshes context unconditionally; an all-zero context batch yields a one-past-end cursor for every SM. The scalar replay retains that input counterexample. A real CUDA boundary check is required before claiming empty-context safety. The compiled SM90 body rejects varlen although the scheduler header has a varlen branch; that branch is not an admitted public device path.

Paged output stride is aligned to the common multiple of SPLIT_KV384 and BF16 row alignment512:1536 elements on SM100. Dense compressed output uses a different nested alignment. SM100 stores only per-row valid positions; SM90 paged stores complete scheduled page tiles, so callers must apply context masks. The tests mask validity before comparing outputs.

## Sparse union and output incidence

Sparse MQA is SM100-only, head_dim128, heads multiple4 up to32. Each row has at most4096 index entries, row capacity divisible4, and sparse block size8/16. A valid prefix length is inferred from ceil(valid KV span/sparse block), clipped to the row's declared maximum. That prefix must be unique, strictly increasing and within the corresponding KV domain. It is not a sentinel-terminated arbitrary sparse list. Optional unaligned ks converts each row's block IDs into token starts `block*extent + ks%extent` before merging. Thus equal raw IDs with different ks residues cannot be assumed to name equal payloads.

Two Q rows share a sorted union of their sparse indices. The metadata kernel partitions a merge path across256 threads and drops a duplicate carried across partition boundaries. It records each consumer's original slot as a split base plus a16-bit offset or absent65535. A common block is fetched once, while each Q still computes its own weighted logit and scatters only to its own compressed slot. [shared_index_union@1](delta/shared_index_union@1/template.yaml) owns this design object; `indexed_gather@1` handles the subsequent payload transfer. A planner descriptor alone does not explain the per-consumer incidence map.

For lists `[0,2,4]` and `[1,2,4]`, union `[0,1,2,4]` retains independent slot orders; dropping the slot map or retaining a merge-partition duplicate changes outputs. The replay checks1024 pairs against independent set union and exact slot reconstruction. The [partial chain](delta/attention-chain.yaml) binds one FP8 split512/sparse8 to64 union entries. Actual source split sizes are512 for FP8 and640 for FP4, giving32/64 or40/80 blocks per split, respectively. The generic union rule exposes split size as a choice; the CUDA Realisation binds this fixed source menu. No measured benefit is implied.

Paged sparse pairs stay inside one consecutive request run and require equal block-table rows. Logical sparse block IDs translate through page tables before data access; source row selection uses the pair's first Q row. Non-paged full, aligned, contiguous splits can use TMA; strict uniqueness plus sorted endpoints proves that the interior has no holes. Partial splits, noncontiguous keys or unaligned starts use generic async copies. The generic last-tensor-block path zero-fills out-of-allocation tokens; it does not remove every row's semantic tail. Padded descriptors use physical block0 with both rows absent. Device scatter still writes a whole sparse block when present; tests mask by each original KV span and prefix length.

## Publication, resources and remaining obligations

Sparse metadata uses per-stream persistent workspace, zero-initialized once outside CUDA graph capture. CTAs reserve split ranges with atomic addition and publish their completion with release atomic addition; the last CTA performs an acquire load, builds the final schedule/header and resets counters. Correct multi-thread/CTA visibility and repeated graph reuse remain device obligations. Non-paged schedules divide split ranges evenly and split at Q-block boundaries; paged schedules cap each entry at eight splits, then sort/rotate per-wave entries. Atomic descriptor allocation may change physical order; the incidence map must keep logical outputs unchanged.

The sparse metadata header pins `use_unaligned_ks` and the generation-time SM count; the compute body checks both on device. Host intentionally checks only the outer byte tensor to avoid stream synchronization. Supplying metadata from a different layout, shape, SM count or request content is outside the composed input contract. Workspace/device-stream initialization and descriptor lifetime must precede the consuming kernel.

Shared SM100 execution separates Q/SF producer, KV producer, SF transposer, MMA issuer and math roles. Q full completion joins TMA bytes with SF UTCCP publication; KV full completion similarly joins raw payload and scale readiness. Tensor-memory empty waits protect accumulator stages until their last load to registers. We reuse `physical_storage@1`, `per_slot_handshake@1`, `warp_specialization@1`, `register_rebalancing@1` as partial matches; fixed warpgroup/tmem signaling and non-CTA barrier event semantics require explicit realization bindings. In particular, the seed rotation@2 CTA-wide event model is not a proof of this protocol. No emitted instruction, CUDA run or race proof is part of these scalar checks.
