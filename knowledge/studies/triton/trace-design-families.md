# Additional Triton NVIDIA design families

Status: representative-design extraction complete; pending independent review. Source-relative paths begin at python/tutorials unless stated otherwise. Existing grouped/persistent traces in trace.md remain pinned; this page resolves the initial unread families.

## Fused row softmax and normalization

02-fused-softmax.py:84-110 loads a power-of-two row with -infinity padding, computes max, approximate exp, sum and normalized output within one program. output_tiling@2 gives one row; reduction_partition@1 supplies max/sum with neutral padding; cross_lane_reduction@1 (reference package) supplies a target-specific reduction realization. It is NOT an online rescaling use: the complete row is resident. :120-175 warmups the kernel to obtain actual register/shared usage, computes occupancy and launches a bounded number of persistent programs that advance row_idx by num_programs. persistent_tile_scheduler@1 fetch=static_stride,grid=actual_num_programs describes this launch. Eight warps and stage2/4 are source policy values; emitted resource data are queried by source but not measured in this study. Empty support is not admitted by this source row formula.

05-layer-norm.py:53-95 computes FP32 mean, then centered variance in a second input pass, stores mean/rstd, and reloads input for affine output. This is a two-pass local centered-statistic instance; centered_moment_merge@1 is not needed because no partial mean/M2 merge occurs here. physical_storage@1 reg holds row-reduction accumulators and gmem holds mean/rstd for backward. :140-220 backward computes c1=sum(xhat*w*dy)/N,c2=sum(w*dy)/N and dx=(w*dy-xhat*c1-c2)*rstd; parameter partials are dy*xhat and dy. striped_locked_partial_accumulation@1 groups=GROUP_SIZE_M captures modulo row assignment and whole-vector lock/first-writer state. Host :267-291 chooses groups by feature size and final reduction reads min(groups,M) slots, avoiding never-initialized scratch. Numeric precision of partials follows the weight dtype before later FP32 combine, so changing scratch precision is not free equivalence.

## Stateless dropout descriptor

04-low-memory-dropout.py:110-145 binds counter_indexed_mask_replay@1 (provisional FlashAttention) to seed plus original flat int32 element offset, tl.rand generator, float32 comparison random>p and output scaling 1/(1-p). Fixed seed123 repeated is a replay of the same invocation descriptor; seed512 is a separate descriptor. The example demonstrates repeated forward calls, not a separately implemented backward. The original offset, not lane/program position, is the random address; changing tile size is legal only if it preserves those offsets and generator rounds. Positive p<1, supported int32 offsets and immutable descriptor are scope conditions. The old FA byte threshold is a source instance, not a mandatory numerical law of the generic rule.

## Attention forward/backward

06-fused-attention.py:48-113 keeps online (m,l,acc). Each score tile sets new max, rescales old denominator/numerator by exp2(old_m-new_m), adds exp2(qk-new_m), then contracts probabilities with V. online_rescaled_reduction@2 (provisional CUTLASS) binds base2 with qk_scale including log2(e). STAGE1 processes earlier causal tiles without element masks, STAGE2 the diagonal block with offs_m>=start_n+offs_n and finite -1e6 sentinel, STAGE3 the full noncausal range. masked_tile_pruning@2 explains tile ranges only on the source's aligned/context contract; finite sentinel error is a numerical premise, not exact removal of masked probability in real arithmetic. FP8 V orientation and non-transposed path are Blackwell-only source choices.

:249-262 checkpoints delta=sum(O*DO) per row; softmax_gradient_row_checkpoint@1 (provisional FlashAttention) supplies that exact row statistic. :267-318 reconstructs p=exp2(qkT-m), accumulates dV=p*DO and dK using ds=p*(V*DO-delta), with causal masking. :320 onward gives dQ traversal and explicit scaling factors. The dK/dV and dQ output ownership differ, but both use the same forward normalization checkpoint and mask coordinates; output_tiling@2 assigns independent derivative tiles. Probability recomputation binds softmax_probability_recomputation@1 (provisional TileLang), with no score/probability matrix checkpoint. Base2 log normalization and ds_scale preprocessing must match across all passes.

## Descriptor scaled MMA and scale layout

10-block-scaled-matmul.py:34-69 describes logical scales [M,K/VEC_SIZE] stored physically [M/128,K/VEC_SIZE/4,32,4,4]. :178-242 loads those blocks, reshapes/transposes to the logical scale matrix for dot_scaled, advances operand K by BLOCK_K/ELEM_PER_BYTE and scale K by rep_k. blocked_scale_digit_layout@1 (new Fuser proposal) binds R_outer=32,R_inner=4,C=4 with scale column k/VEC_SIZE, exactly the same digit order. The code sequence reshape(rep_m,rep_k,32,4,4).trans(0,3,2,1,4) inverts that storage. For original row33, scale-column5, physical digits [0,1,1,1,1] distinguish row-digits from ordinary contiguous row order.

VEC_SIZE=16 NVFP4 versus32 MX formats is a numerical metadata group, distinct from packed data ELEM_PER_BYTE=2 for E2M1 or1 for E4M3. block_scaled_instruction_operands@1 describes the actual intrinsic scale operands; block_scaled_partial_accumulation@1 is only an algebraic comparison and is not bound to this implementation; compute_instruction_selection@2 instruction=tcgen05_mma,operand_source=ss,accum_dtype=f32 supplies the NVIDIA instruction choice. Native dot_scaled lowering/scale-fragment identity remains a realization obligation; the source does not quantize arbitrary inputs in this kernel.

## Dependent grid launch

11-programmatic-dependent-launch.py:28-67 binds early_dependent_grid_launch@1. It computes program offsets, calls gdc_wait before x/y loads, then triggers dependents before its own arithmetic/store. Trigger releases scheduling only when all predecessor programs trigger or finish; wait establishes completed prior writes. USE_GDC and host launch_pdl must agree. ## Explicit distributed layout

Gluon 02-layouts.py:30-120 and :160-175 define hierarchical register/lane/warp factors, with concrete S=[2,4],T=[16,2],W=[2,2],order=[1,0]. blocked_thread_register_layout@1 maps a 64x16 block with eight registers/thread; shape128x128 adds 16 block repetitions and128 registers/thread before liveness. ## cp.async, TMA and shared-memory pipeline

Gluon 03-async-copy.py:41-65 issues cp.async into shared, commits the group, waits zero pending groups, then reads/stores. async_transfer@1 binds mechanism=instruction,complete_point=wait_group_then_barrier as a conceptual required publication; actual compiler/backend provides the relevant collective synchronization, not a hand-invented explicit barrier. :258-331 pipelines with num_buffers slots, preloads num_buffers-1 generations, issues another before wait_group(num_buffers-1), reads oldest ready slot, then drains with decreasing wait thresholds. physical_storage@1 and source-specific group completion protect slot generations; multi_buffer_rotation@2's CTA-barrier proof cannot alone prove this asynchronous schedule. Tail copies are predicated at original coordinates.

Gluon 04-tma uses descriptor loads with expected-byte mbarriers and matching shared layouts; 05-wgmma/06-tcgen05 distinguish Hopper warpgroup register accumulators from Blackwell tensor-memory accumulator/commit completion. These bind async_transfer@1 controller, physical_storage@1 smem/tmem and compute_instruction_selection@2 wgmma/tcgen05 with selected operand source; actual descriptor/MMA completion is retained as the backend realization. Exact selected witnesses and differences continue below.

## Three-role warp specialization

Gluon 08-warp-specialization.py:96-123 explicitly requires async proxy fences even when shared store/load and TMA are sequenced by cross-role mbarriers. :124-232 has independent load and store rings, each with ready/empty barriers and its own modulo/phase; :275-307 launches one load warp and one store warp with24-register budgets plus default compute warps4/8, rounding physical warp allocation to warpgroups. load_compute_store_role_pipeline@1 captures both rings, including store_wait before an output slot becomes empty. warp_specialization@1 has roles but no independent store-warp/ring field, so it is not claimed sufficient by itself.

## Indexed row descriptor transfer

Gluon 09-tma-gather-scatter.py:190-277 and :355 onward bind indexed_descriptor_row_transfer@1 on Blackwell. Descriptor block=[1,BLOCK_Y], row offsets count>=8, minimum columns=(32/element_bits)*8 and common column origin16-byte aligned. Offset-layout lane bases are all zero with required register bases [1],[2]; source converts from coalesced offset loads to the supported slice layout. Gather allows negative/OOB indices and zero fills; scatter disallows negative coordinates and needs distinct destinations for a unique-output contract. One expected-byte barrier covers rows*descriptor_block_bytes before shared reads; store direction fences shared writes and drains source reads before reuse. This is not a page-size lookup rule.

## Resolved cross-tile epilogue alias

Gluon 07-persistence.py:627-724 binds spare_operand_slots_epilogue_alias@1 S=4,output_slices=two for BM128,BN256,BK64. B ring5 contains three live next-tile prefetches, leaving two next producer slots. mma.wait(0) retires previous reads before those slots hold two N-half output slices; store_wait(0) precedes the next TMA refill. Different A/barrier ring4 and B ring5 indices are retained. This replaces the earlier unresolved alias gap with a narrow schedule-specific rule and outline, not an unrestricted alias claim.

## Exact async MMA / copy witnesses

Gluon 05-wgmma.py:338-380 registers operand TMA byte count, loads A/B into shared, waits phase and issues warpgroup_mma with shared B view; warpgroup_mma_wait(0) precedes shared reuse and final C staging. The B transpose is a shared descriptor view, not a physical matrix transpose. Gluon 06-tcgen05.py:210-246 uses tensor-memory accumulator and tcgen05 commit to mbarrier, with use_acc=false on the first generation instead of separately clearing TMEM. Both bind compute_instruction_selection@2/physical_storage@1 with distinct accumulator realizations; async completion remains operation-specific.

Gluon 10-tcgen05-copy.py:5-74,:117-142 supplies ordered_async_engine_chain@1: tcgen05 copy/MMA/commit share engine execution ordering. A later engine copy can overwrite TMEM only after prior engine MMA consumes it, while generic SM shared writes still need proxy publication and external reads need commit/wait. This is not the DRAM→shared-only async_transfer@1 realization.

Gluon 11-tcgen05-mma-scaled.py:124-174 allocates scale TMEM with TensorMemoryScalesLayout independently of accumulator TMEM; A logical K is packed descriptor bytes times ELEM_PER_BYTE. Scale shape=[M or N,BLOCK_K/VEC_SIZE], B is passed as a transposed shared operand. Later tcgen05_copy staging loads scales from shared into this special TMEM format and chains into scaled MMA. blocked_scale_digit_layout@1 supplies the compatible global scale packing, ordered_async_engine_chain@1 the copy/MMA completion, and block_scaled_instruction_operands@1 the actual encoded-format/scale-coordinate contract. Scale storage is not ordinary accumulator TMEM interpreted with the same layout.

## Cluster launch control

Gluon 12-cluster-launch-control.py:67-88 allocates a 16-byte response and parity mbarrier; every active tile requests cancellation before compute, waits the response after output stores, extracts success and next program ID, then toggles response phase. :154-184 only enters the next tile while scheduler.has_work. This retains response storage until all required role reads and hides cancellation latency behind tile compute. Uncancelled native launches retain ownership.

Strict launch_cancellation_work_reuse@1 does not directly bind: advance extracts program_id even on a failed response. launch_cancellation_work_reuse@2 coordinate_decode=speculative_nontrapping records the actual pattern conditionally, requiring failed extraction be nontrapping and all coordinate-dependent uses remain success-guarded. The source establishes the loop guard, not native failure-accessor semantics. This is a precise realization obligation rather than an implementation audit or an assertion that the old rule already covered it. Failure of that premise would require moving extraction under the success branch; no source change is made here.

## Scaled-instruction reuse correction

The earlier block_scaled_partial_accumulation@1 references above are algebraic comparisons only, NOT a binding of the selected hardware implementation. That rule requires explicit raw accumulator reset/promotion, which dot_scaled/tcgen05_mma_scaled does not expose. block_scaled_instruction_operands@1 now owns the actual source design: encoded data and scale tensors remain separate inputs to the instruction, with independent packed-byte and logical-group coordinates. Native rounding/scale fragments remain its explicit obligations. Existing compute_instruction_selection@2 still identifies the instruction family, but its singular operand-type premise cannot silently express every mixed E4M3/E2M1 pair; the new rule records those format pairs.

## TMA publication versus source-read retirement

Gluon 04-tma.py:133-164 is an actual two-CTA message handoff: CTA0 shared-stores offsets+1000, proxy-fences, issues TMA store, then store_wait(0,read_only=false) before a GPU release store to ready. CTA1 acquire-polls ready before issuing its descriptor load and waits its expected-byte barrier before reading. staged_async_output_store@1 (provisional CUTLASS) binds stages=1 with a separate destination-write completion before publication. A source-read-only wait would grant shared reuse but would not justify ready=1. This is the precise completion distinction already present in that rule's output-observation obligation. Native two-CTA progress and initialization are source realization obligations, not additional random tests.

## Convolution and im2col geometry

Gluon 13-conv-im2col.py:959-1045 loops r,s,channel-block with ci_num_blocks=ceil(Ci/BLOCK_K), tracks original weight k_offset=(r*S+s)*Ci+channel_block*BLOCK_K and asks TMA to zero-fill input channels beyond Ci. An unaligned channel tail may read weights from the next tap's contiguous region, but those multiply zero input values. The binding requires the admitted finite multiplication/zero contract; 0*NaN/Inf is not silently treated as zero. mma.wait(0) precedes single-buffer refill, TMA byte expectation covers input plus weight and barrier phase toggles after every load generation.

Host :1048-1120 constructs NHWC input and Co,R,S,Ci weights, output_h=(H+2pad-R)//stride+1, output_w similarly. Descriptor lower corner=(-pad,-pad); upper_h=(out_h-1)*stride+1-H-pad, similarly W, so traversal spans exactly output spatial positions including multiple batches. implicit_patch_contraction@1 (provisional CUTLASS) binds patch_storage=on_load with dummy depth/filter-depth1, depth stride/dilation1,pad0; 2D stride and nonnegative zero padding match the rule. Hopper WGMMA versus Blackwell tcgen05 is a realization, not another convolution algorithm. Explicit intermediate im2col matrices in tutorial examples compare the same coordinate contract; no external CUTLASS implementation was reopened.

## Multi-CTA reduction / instruction atoms / multicast

It is distinct from remote multi-GPU multimem addresses.

## Four-role multi-CTA matmul

Gluon 14-multicta.py:738-834 guards work coordinates by cancellation success and has three consumer roles acknowledge each shared control slot after completing its tile. :835-870 CLC producer waits all three acknowledgements before reusing the ring slot, decodes successful coordinates once and broadcasts packed M/N through a separate ready barrier. launch_cancellation_work_reuse@1 binds participants=3 per response slot (one independent instance per ring slot); unlike tutorial12 this caller guards coordinate extraction. Control ring depth is ACC_STAGES.

:871-970 gives load, MMA and epilogue roles independent counters. STAGES input slots protect shared operands until engine completion sends load_empty; ACC_STAGES TMEM slots protect accumulators until epilogue captures every slice; SUBTILE_STAGES shared slots protect async output store sources. SUBTILE_FACTOR changes N slice width separately from slot count. staged_async_output_store@1 binds stages=SUBTILE_STAGES over those output slices, while physical_storage@1 tracks TMEM until its last load; TMEM can retire before the global stores finish because stores read captured shared values. Required proxy ordering for generic shared stores remains a native realization obligation.

:972-1028 obtains MMA arrival count from descriptor_union_completion_count@1 rather than treating it as an independent knob. python/triton/experimental/gluon/language/nvidia/blackwell/__init__.py:665-700 enumerates CTA issuers admitted by any descriptor, counting a CTA once and skipping odd ranks for two-CTA atoms. Those derived arrivals initialize load_empty and acc_ready; byte expectations remain separate. With two CGA bits and nonzero-basis masks A={bit0},B={bit1}, admitted issuers are {0,2} union {0,1}={0,1,2}; two-CTA atom filtering leaves {0,2}. Counting per-descriptor totals would double-count CTA0.

The planar tile mapping at :668-706 binds striped_snake_rasterization@1 minor_axis=m or n,strip_width=GRID_TILE_WIDTH. It alternates major direction across strips and handles a short last strip with actual width. This is a permutation independent of cancellation ownership and all three buffer-depth choices. A generic “persistent matmul” label would lose these independent controls.

Dropout generator pin: python/triton/language/random.py:5 fixes default Philox rounds10, :89-110 decomposes the original offset into low/high counter words, and :147-155 converts the generated integer word to uniform float for the comparison. This is a different generator/threshold binding from the FA source example; replay uses this exact Triton binding, not merely the name Philox.
