# Additional CCCL design families

Status: representative extraction complete; pending independent review. Paths below start at cub/cub in the retained source. This page replaces the initial possible-match inventory with concrete source bindings.

## Histogram privatization and local run updates

agent/agent_histogram.cuh:295-399 flushes a CTA-private table only after a CTA barrier, decoding each nonzero private bin and atomically adding to final output. The table can live in shared memory, per-CTA global storage or a blended CTA-parity assignment (:646-675). Privatization and within-thread update coalescing are separate choices in privatized_bin_accumulation@1. With decoded thread bins [2,2,5,5,5], local_equal_runs emits two additions (2,+2),(5,+3) rather than five. Equality is on decoded bins, not original samples; different samples in the same bin may coalesce. Invalid bin -1 is ignored. Integer overflow and initialized output remain explicit premises. This differs from first_writer_atomic_combine@1: final output is separately initialized and no producer is an elected first numeric writer.

## Stable merge path

block/block_merge_sort.cuh:41-61 searches the number i of A entries in output prefix d, with B prefix j=d-i. It advances i when B[j-1] is not strictly smaller than A[i], so A wins equivalent ties. device/dispatch/dispatch_merge.cuh:106-134 computes tile diagonals using the selected consumer agent's items_per_tile, including fallback selection; using the nominal policy tile would be wrong if the fallback changes it. agent/agent_merge.cuh:180-270 loads two disjoint shared slices (async direct-to-shared with commit/wait or register staging with CTA barrier), computes per-thread diagonals and performs short serial merges. A final barrier retires key reads before shared storage is reused by the store phase.

merge_path_partition@1 binds tile_items to the actual selected agent. Example A=[1a,3a],B=[1b,2b],d=1 chooses A prefix1/B prefix0 and preserves 1a before 1b. physical_storage@1 shared-buffer lifetime plus async_transfer@1 readiness describe staging; the diagonal partition supplies a new bounded-output-work choice absent from generic rectangular output_tiling@2.

## Radix / onesweep stable scatter

agent/agent_radix_sort_onesweep.cuh:321-356 publishes per-digit PARTIAL counts, walks earlier tiles until an accumulated/global prefix appears, then installs the complete prefix. :514-541 initializes global_offsets[bin]=global_bin_base[bin]-local_digit_prefix[bin] and adds earlier-tile same-bin count. :690-713 obtains stable local radix ranks, scatters to shared, resolves prefixes, scatters keys globally, then gathers/scatters associated values using the same ranks. Thus a key at locally sorted index idx writes idx+global_offsets[digit]. This is algebraically base(bin)+earlier_tile_count(bin)+within_bin_rank, the program of stable_radix_digit_scatter@1.

CountsCallback at :295-321 publishes counts during ranking; :399-459 short-circuits a full tile when all items share a digit. It copies keys/values contiguously but still resolves/publishes count-prefix effects. A short final tile cannot assume the shortcut. Separate upsweep/downsweep agents materialize counts in separate stages; onesweep combines count lookback and scatter in one pass. These are count_schedule alternatives, not different stable-sort contracts. Ordered_prefix_lookback@1 explains the predecessor-prefix invariant per digit, but this source uses packed count/status flags and a scalar per-bin traversal rather than the CUB scan warp-window realization; status layout is not copied from the old rule without a realization binding.

## Select / partition stable ranks

agent/agent_select_if.cuh:272-280 requires blocked input items for flag scan/scatter and a full warp for the lookback callback. :660-677 direct scatter writes selected items at their exclusive flag prefix; :701-729 two-phase scatter first packs CTA-local shared positions, then threads cooperatively stream that packed prefix. stable_sparse_support_compaction@1 (provisional FlashInfer) binds support_layout=stable_compact,row_count=1,row_capacity=N, key translation=identity, per-occurrence metadata=the original payload/index, original validity=the selection predicate. Causal/segment cuts are vacuous for this generic row; duplicate payloads remain distinct occurrences. physical_storage@1 level=smem supplies two-phase exchange, versus direct gmem stores. No new compaction identity is needed.

Distinct-output partition at :834-860 uses selected and rejected prefix counts for two destinations; one-output partition has a separate reject-placement convention and must not inherit stable reject order by assumption. The single-output mapping is resolved below.

## Radix top-k: actual binding

agent/agent_topk.cuh:503-539 locates the unique bucket with prev<k<=cur and updates residual k=k-prev and candidate len=cur-prev. :542-591 fences histogram writes, elects the LAST ARRIVING CTA via atomicInc, prefixes bins, selects the bucket and resets histogram for the next pass. This is not Fuser's designated-coordinate completion. :595-646 re-streams original input if the prior candidate length exceeds buffer capacity; otherwise it uses compacted candidate keys and original index metadata. Strict winners allocate from the front; boundary ties use a back counter and only back_pos<needed writes output[k-1-back_pos].

radix_threshold_selection@2 (provisional TransformerEngine) binds key_bits=32,digit_bits to a supported 4/8-bit source specialization,tie_policy=any for the finite FP32 unsorted case. It supplies residual rank and exact tie quota. Original input re-streaming rather than candidate buffering is an independent storage-capacity choice to extract; a full sort is not selected here. No smallest-index tie promise comes from atomics. Batched/cluster top-k has further resident/streaming and deterministic tie choices and remains active work.

## Nontrivial run encoding

agent/agent_rle.cuh:353-434 computes both head/tail flags with predecessor/successor items across tile boundaries. It emits pair (head&&!tail, !head||!tail): a singleton contributes (0,0), and a nontrivial run contributes one head plus a count for every member. :448-515 scans pairs using ReduceBySegmentOp; thread/thread_operators.cuh:312-360 makes the operation associative and noncommutative: head counts add, but the suffix value resets when the right operand contains a new head. This is why reduction_partition@1 with commutative scope is unsuitable. :524-610 compacts run offsets/lengths with warp time-slicing as an alternative scratch schedule. Nontrivial-run output is a distinct caller contract from DeviceRunLengthEncode of all runs. Concrete segmented state and end-of-input flush are the next extraction step.

RLE completion: agent_rle.cuh:1026-1078 writes total nontrivial-run count and the last inclusive suffix length at end of the last tile/streaming partition; without that flush, the last nontrivial run has no following head to trigger its length write. head_reset_scan_state@1 expresses the associative noncommutative pair operator and its head/suffix interpretation. ordered_prefix_lookback@1 composes across tiles using that operator. Input [A,A,A,B,C,C] tiled after item2 must yield nontrivial runs (offset0,length3),(offset4,length2), not split the A run and not retain singleton B.

Partition variant resolved: agent_select_if.cuh:834-860 gives two-output stable selected/rejected prefixes; :868-900 single-output mode places selections in forward order and rejections at N-1-rejected_prefix, reversing reject order. stable_sparse_support_compaction@1 binds selected output only; the rejected stream's explicit reversed mapping belongs in this partition instance, and is not passed to a consumer requiring stable rejects. Both streams remain disjoint because selected_count+rejected_count=N. A generic stable compaction rule must not be used to claim stable single-buffer partition.

## Batched / cluster top-k storage and scheduling

agent_batched_topk.cuh:225-227 enqueues large segments with atomic queue positions and per-segment tile counts; small segments run block_topk in one CTA (:300-321). :350-393 last-arrival epilogue scans the queued tile counts into work offsets. This composes persistent_tile_scheduler@1 over a worklist with online_group_work_decode@2 scalar prefix inversion; segment sizes determine the threshold split, not a new top-k numerical contract.

agent_batched_topk_cluster.cuh:253-290 normalizes signed zero only when an explicit index tie-break requires equivalent keys to tie. Deterministic smaller-index mode scans CTA ranks ascending with leader last; larger-index preference reverses scan and residency. :2895-2907 splits local chunks into resident and overflow windows. :2919-2984 re-histograms resident values and re-streams overflow each radix pass, overlapping resident histogram work with first reloads. :3137-3217 selects deterministic original-index final scan versus nondeterministic placement. The stream direction alternates between histogram passes to keep turnaround chunks; it is not permission to reverse a noncommutative scan.

resident_overflow_repeated_scan@1 captures retained window/streaming choices; radix_threshold_selection@2 supplies the boundary key for admitted 16/32-bit,4/8-bit finite cases. Deterministic smallest-index ties bind tie_policy=smallest_index only after zero normalization and ordered final filter; larger-index preference is a deliberate extension to the old rule's tie menu, documented here rather than mislabeled smallest_index. Original candidate-buffer fallback in agent_topk.cuh:595-646 binds bounded_candidate_materialization@1 and is separate from retaining original unfiltered resident chunks. Small segments collapse to rank0 when all data fit and the tuning threshold permits it; inactive cluster ranks do not contribute histogram or prefix arrivals.

## Duplicate-aware set operation partition

agent_set_operations.cuh:107-150 balanced_path starts from ordinary MergePath, finds equal-run beginnings in both inputs, balances progress through those runs and returns an extra B-coordinate star at alternating equal-key boundaries. Ordinary merge_path_partition@1 cannot replace this: independently cutting equal runs may change multiset intersection/difference multiplicities. :156-207 serial intersection emits min(countA,countB) items from A; :578-637 applies balanced per-thread ranges, packs partition coordinates into 16-bit halves, performs the serial operation and scans output popcounts for compact destinations. Union/symmetric difference/difference change the per-key multiplicity and source payload, not the prefix allocation invariant. A duplicate-aware partition extension remains to be written; source mechanism and missing expressible choice are identified, not marked complete.

## Adjacent input aliasing and find pruning

agent_adjacent_difference.cuh:130-245 loads the tile before output stores and, for MayAlias=true, consumes a separately snapshotted predecessor/successor at each tile boundary. AgentDifferenceInit snapshots those boundary values before the in-place kernel. This preserves input values that another CTA could otherwise overwrite; adjacent_boundary_reuse@1 does not apply because its source is expensive common-function endpoint evaluation, not arbitrary in-place input preservation. The required boundary checkpoint is another explicit delta, not generic storage alone.

agent_find.cuh:150-220 gives each CTA increasing grid-stride tiles. A shared copy of the global atomic minimum allows exit when found_position<tile_offset; because all future indices are at least tile_offset, none can improve the current first match. A stale relaxed value only causes extra work, never a missed earlier match. Each CTA publishes its local first result with atomicMin and exits. This monotone bound differs from value-threshold top-k pruning and will be recorded separately.

## Vectorized irregular copy

agent_batch_memcpy.cuh:204-255 derives an interior destination-vector-aligned range while reserving input read padding needed for unaligned word reconstruction. :265-305 copies bytewise if the interior is empty, otherwise handles scalar prefix, aligned vector interior and scalar suffix. This is a source realization of boundary_predication@1 boundary_kind=alignment_prefix plus output_tiling@2 thread-owned disjoint byte ranges; instruction width comes from a legal aligned interior, not an assertion that both raw pointers are vector-aligned. The size-based cooperative work assignment is resolved below as size_class_cooperative_assignment@1.

## Reproducibility and deferred lengths

Device reduce has a distinct numeric design beyond fixed-tree summation: device/dispatch/dispatch_reduce_deterministic.cuh:52-95 selects ReproducibleFloatingAccumulator<float/double> with default fold3. detail/rfa.cuh:45-103 allocates six floating components (three primary plus three carry), float bin width13/double40. :249-321 chooses/updates the exponent bin anchor; :322-378 deposits with forced low-bit additions and residual propagation; :379-402 renormalizes carry bits; :409-463 aligns and merges binned states. binned_floating_accumulator@1 captures that representation, keeping its numerical proof obligations open instead of applying scalar reduction associativity. Kernel source :130-198 initializes shared bin constants and trims a device-resolved deferred grid; both reduction passes must use the same active grid. Very large deferred sizes advance input in 32-bit chunks while retaining the accumulator; integer loop chunking does not reset numerical state.

## Remaining family progress

Block top-k is concretely AIR radix selection, not sorting: block/specializations/block_topk_air.cuh:56-71 states MSB-first histograms over matching-prefix candidates, then partition; :174-192 counts only valid blocked items and reverses digit bucket order for max. It reuses radix_threshold_selection@2 for supported finite key/digit widths, plus physical_storage@1 for two histogram buffers. No key movement occurs during threshold discovery.

Batched memcpy work assignment: agent_batch_memcpy.cuh:595-650 classifies thread-, warp- and block-cooperative buffers; :1030-1123 scans BLEV counts for a global queue prefix, partitions descriptor IDs by size class, enqueues large BLEV work and services warp/thread classes locally. All indices preserve original descriptor identity. ordered_prefix_lookback@1 supplies queue prefix, stable radix/count partition supplies within-tile class grouping; size thresholds are policy, not semantic differences in copied bytes. This is an execution-granularity choice to expose in the final delta rather than a new memcpy numerical operation.

Thrust CUDA linkage was read through concrete wrappers: sort.h:65-214 selects CUB merge sort for comparator paths versus DeviceRadixSort for supported primitive-key paths; scan_by_key.h:63-119 delegates to CUB scan-by-key but overrides accumulator type for compatibility. That override is a numeric-contract difference and must be pinned, not assumed identical to CUB public default accumulation. binary_search.h has no CUDA-specialized implementation; the concrete generic parallel search is resolved below. Set-operation wrappers call the duplicate-aware CUB path already traced. The following section resolves generic Thrust mapping, segmented sort/reduce and exact by-key reset/neighbor bindings; the final inventory includes those representatives.

## Completed public-family follow-through

size_class_cooperative_assignment@1 now exposes the memcpy TLEV/WLEV/BLEV partition and queue choice. kernels/kernel_segmented_reduce.cuh:130-227 uses a related maximum-size launch choice: one thread/subgroup for small segments, warp for medium and CTA for large. global_segment=block*segments_per_block+thread/subgroup_width; lane zero stores only its segment result, including the caller init. Each segment's begin/end is independent metadata, not one global strided reduction. Empty segment uses the initial-value policy rather than reading nonexistent samples. Bound threshold and cooperative widths to the actual selected policy; numerical trees may differ across classes.

agent_segmented_radix_sort.cuh:130-175 handles a small segment in one BlockRadixSort pass, explicitly fills invalid keys with extreme transformed sentinels and stores only num_items; keys and associated values share the permutation. The iterative large segment path counts digits, prefixes bins and scatters within that segment, binding stable_radix_digit_scatter@1 with segment-local bin base. Descending order reverses bin order, not segment identity. An empty segment performs no sort/store. The source's raw extreme sentinel construction for FP64 is not the same as simply filling floating infinity.

agent_scan_by_key.cuh:310-385 loads key/value tiles, derives flags from adjacent-key inequality, zips flag/value pairs and uses the head-reset operator. Later tiles load the preceding input key to decide whether their first item continues a segment. head_reset_scan_state@1 supplies reset semantics; ordered_prefix_lookback@1 carries that state; exclusive mode AddInitToScan emits init at heads and combines init with non-head prefixes. AgentReduceByKey uses the same ReduceBySegmentOp and head discontinuities (agent_reduce_by_key.cuh:192-238); it emits one key/reduction per completed logical run rather than every prefix. RLE is that family with specialized count/nontrivial-run predicates. These reuse actual state fields, not a commutative reduction substitute.

Thrust generic vector binary search (system/detail/generic/binary_search.inl:41-119) uses for_each over zipped queries/results, one scalar lower/upper-bound search per query. output_tiling@2 executor=thread,index_map=identity partitions independent query outputs; lower/upper tie semantics come from scalar search comparator, with no warp-cooperative search inferred. CUDA gather.h:24-38 composes permutation input iterator with transform(identity): result[i]=input[map[i]]. generic scatter.inl:24-33 copies to a permutation output iterator: result[map[i]]=input[i]. output_tiling@2 custom map binds each; repeated gather addresses are legal, but repeated scatter destinations need a caller conflict policy because this implementation has ordinary stores, not atomic reduction. CUDA sort delegates to previously traced CUB merge/radix paths; scan-by-key's accumulator override is retained as an interface difference. No distinct additional GPU algorithm is inferred from wrappers.

Deterministic largest-index ties now bind radix_threshold_selection@3 tie_policy=largest_index with descending original-index boundary emission; version2 bindings translate without field changes. The source normalizes signed zero for explicit index ties. Histogram sweep direction/residency is derived from requested tie order, not an independent semantic freedom. This completes the previously named tie-menu delta without changing the shared TransformerEngine file.

## cudax cooperative public surface

cudax/include/cuda/experimental/coop/__group/mapping/binary_partition.cuh ballots the predicate within the previous lane mask, selects true/false mask and obtains subgroup size/popcount plus rank/popcount(mask & lanemask_lt). group_by.cuh instead groups consecutive logical units, requiring exhaustive division or excluding the partial group. These are actual membership maps, not assumptions that physical lanes remain contiguous.

coop/__algorithm/reduce.cuh:60-153 delegates thread/warp/block reductions to CUB; block broadcast aliases reduction scratch with one shared result only after a barrier, then uses a publication barrier and a retirement barrier before scratch reuse. :175-245 cluster path maps one root shared allocation through cluster_map_shared_rank, writes one partial per CTA between cluster joins, reduces on the root warp and optionally broadcasts from the root with a final reader-retirement join. This differs from the replicated-per-CTA partial tables; physical_storage@1 level=smem plus partitioned commutative reduction binds the root-only table. :248-315 extends the same hierarchy through a grid partial table and cooperative grid synchronization; its static extents and cooperative-progress/lifetime are required caller premises.

:316-345 handles an arbitrary masked warp subset with rank-relative shuffle_down at strides1,2,4 and an optional broadcast from countr_zero(mask). sparse_lane_rank_reduction@1 expresses this new sparse/non-power-of-two, ordered collective; cross_lane_reduction@1 only offers power-of-two commutative XOR groups. A sparse three-lane string witness distinguishes the mappings. :354 onward permits only static contiguous groups of whole warps, stores each warp partial at its physical warp index (not reused logical group rank), and synchronizes before shared reuse. Independent group mappings must not alias scratch merely because both label a warp rank0.

The memory entry points do not add an unexamined device-copy algorithm: __copy_bytes/memcpy_batch_tiles.cuh:42-90 linearizes a contiguous tile origin through mixed-radix extents/strides; :128-196 dispatches cuMemcpyBatchAsync on CUDA13+ or individual cuMemcpyAsync on older toolkits. __fill_bytes/fill_bytes_mdspan.cuh:174-205 rejects interleaved stride order, sorts/simplifies strides, flips negative strides with the base adjusted, then fills contiguous inner tiles through driver memset. Padding holes are not filled as tensor elements. This is descriptor lowering to driver operations, unlike the CUB device batch-copy kernel already traced.

cudax streams/graphs/STF/execution modules supply launch/lifetime orchestration, and cuco wrappers are an external cuCollections integration boundary owned by Worker E. They are not silently counted as additional examined device algorithms. The concrete group and memory public families above close the completion-audit addition.
