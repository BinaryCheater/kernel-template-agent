# Replay execution decisions

This implements the authorized [replay plan](template-replay-plan.md). The experiment has two boundaries: consolidation publishes a file library, and the evaluator passes only a frozen task package to a separate implementation session.

| Question | Execution choice and observable |
|---|---|
| What is it? | A bounded kernel replay experiment over a frozen canonical file library; source studies remain provenance inputs. |
| Which claim? | Determine whether an implementation agent can select and instantiate the accumulated rules, and identify concrete guide failures. Four basic runs precede disclosure and harness comparisons. |
| Dependencies? | Existing candidate YAML and outlines are available. GPU language support, production-oracle agreement and persistent session recovery require real smoke runs before implementation. |
| Scope? | The plan's three GEMM and three causal attention shapes on GB10; exact ABI, tolerances, cache policy and budgets are frozen per case. |
| Failure? | Conflicting identities, missing outlines, vague guides, invalid numerical output, failed compilation, weak tuning, environment failure or missing transcripts. No silent model/language substitution. |
| Observable? | Complete source mapping, withheld list, read/session records, retained candidates, validation errors and per-shape timing samples. A failed run remains a result. |
| Knobs? | Frozen case manifest owns language, suite, tolerances, 60-minute active budget, 20 evaluation batches, three shapes per batch and provisional ratio aim 0.90. Queue wait is separate. |
| Repair? | Coordinator diagnoses retained failures, edits the owning guide or harness, freezes a new revision and starts a fresh implementation session with an adjacent shape. |
| Decision and cost? | Use file catalogs and request-file evaluation first; alternatives are an early retrieval service or direct agent access to evaluator code. Switching later requires new packages/runs, preserving prior outcomes. |

Experimental implementation sessions use isolated persistent homes under KTA_DATA, native credential links and the existing agents adapter. Workspace write restrictions protect package ownership where available; read isolation remains instruction-only and must be reported. Evaluator code, mathematical and production references, private seeds and earlier solutions stay outside the implementation package. Requests carry candidate snapshots to the coordinator, which dispatches GPU work through Executor and the shared worker host lock.

No commit is authorized. Deploy the existing committed control-plane code from a clean detached checkout; transfer experimental payloads by content identity as job inputs. Label their uncommitted status honestly rather than presenting them as clean WP delivery evidence. Preserve that checkout and all failed runs. No running service, global configuration or system package change is needed.

Pending obligations: validate every menu path and source disposition; check package leakage and candidate mutation; verify TileLang compilation and execution; verify production references against mathematical references; verify session start and resume; verify exclusion with the shared GPU schedule; preserve exact settings and available accounting. These obligations gate the relevant next step rather than being inferred from an agent report.

## User steering: direct remote experiments

The user subsequently authorizes temporary direct remote connections for experiment execution and compilation, and prioritizes a capable native Codex environment over completing the product backend. Use the simplest recorded native sessions and direct remote commands when that avoids harness friction. The request-file/Executor path above is optional for this experiment, not a requirement to implement. Keep evaluator-owned references, frozen tasks, persistent sessions, shared GPU exclusion and retained results. No backend/frontend completion is part of this goal.

## Prepared follow-up runs

The disclosure variant keeps the attention task and semantic library unchanged. It adds twelve category-card files derived from frozen metadata and injects a 2,262-byte starting prompt/menu; full catalog and guides remain readable. Its exact prompt is retained. Native first-request input tokens measure the actual initial context, including the harness system prompt, rather than estimating tokens from bytes. Category labels are retrieval cues, not applicability restrictions.

The matched DSH case is attention self-selection with the ordinary full catalog, selected before the attention self-selection outcome is known. Both packages have identical TASK.md, TEMPLATE_USAGE.md and all rule/outline/guide bytes. Neither follow-up package contains evaluator source or prior candidates. They will launch after the four originals; no retrieval service is introduced.
