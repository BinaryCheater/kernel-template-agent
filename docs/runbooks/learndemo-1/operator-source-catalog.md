# NVIDIA GPU kernel sources and reading routes

Choose by the question in the [operating procedure](operator-library-playbook.md). Only NVIDIA device paths are in scope. Links point to files verified in upstream Git trees on November 4, 2026. Each row gives a suggested trace and a witness to collect. Examples isolate mechanisms; framework integrations locate production callers. Record the dependency version used by the caller when two repositories participate in one trace.

## Two production entry points

**Humming.** Start at [vLLM mixed-precision linear adapter](https://github.com/vllm-project/vllm/blob/c1d8fade8d392a010b80aaa0de55f6f0f02a4ebb/vllm/model_executor/kernels/linear/mixed_precision/humming.py). Follow can_implement, weight preparation, and apply_weights in that order. The [MoE caller](https://github.com/vllm-project/vllm/blob/c1d8fade8d392a010b80aaa0de55f6f0f02a4ebb/vllm/model_executor/layers/fused_moe/experts/fused_humming_moe.py) has a different caller contract. In Humming follow [GEMM configuration](https://github.com/vllm-project/humming/blob/145bed14896b34b35bd6934dc35063975b47ee28/humming/ops/gemm.py) → [JIT kernel construction](https://github.com/vllm-project/humming/blob/145bed14896b34b35bd6934dc35063975b47ee28/humming/kernel/humming.py) → [SM90 policy](https://github.com/vllm-project/humming/blob/145bed14896b34b35bd6934dc35063975b47ee28/humming/tune/sm90.py) → the selected device mainloop. Inspect the [warp-specialized implementation](https://github.com/vllm-project/humming/blob/145bed14896b34b35bd6934dc35063975b47ee28/humming/include/humming/kernel/humming_ws.cuh) only if selected. Hold format and device fixed and change M. Record the candidate set, chosen tile and resource guard. Then follow one packed code and its scale with [zero-point tests](https://github.com/vllm-project/humming/blob/145bed14896b34b35bd6934dc35063975b47ee28/tests/kernels/humming/test_zero_point.py). For selection boundaries consult [SM90 heuristic tests](https://github.com/vllm-project/humming/blob/145bed14896b34b35bd6934dc35063975b47ee28/tests/test_sm90_heuristics.py). Separate representability, emitted candidates and policy preferences. Humming credits Marlin and DeepGEMM; record lineage when comparing shared mechanisms.

**DeepGEMM.** Start at [GEMM API and dispatch](https://github.com/deepseek-ai/DeepGEMM/blob/5081f8513af57e61696de4f4f04b0e707ffb503e/csrc/apis/gemm.hpp). Compare the contiguous and masked M-grouped entry points. For a group with fewer valid rows than its capacity, trace which output rows are owned and which may be touched. Follow [tile scheduler](https://github.com/deepseek-ai/DeepGEMM/blob/5081f8513af57e61696de4f4f04b0e707ffb503e/deep_gemm/include/deep_gemm/scheduler/gemm.cuh) and, for the corresponding SM90 route, [host specialization](https://github.com/deepseek-ai/DeepGEMM/blob/5081f8513af57e61696de4f4f04b0e707ffb503e/csrc/jit_kernels/impls/sm90_fp8_gemm_1d2d.hpp) → [device implementation](https://github.com/deepseek-ai/DeepGEMM/blob/5081f8513af57e61696de4f4f04b0e707ffb503e/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh). On SM100 read [FP8/FP4 mainloop](https://github.com/deepseek-ai/DeepGEMM/blob/5081f8513af57e61696de4f4f04b0e707ffb503e/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh) with the [scale layout contract](https://github.com/deepseek-ai/DeepGEMM/blob/5081f8513af57e61696de4f4f04b0e707ffb503e/docs/scaling-factor-format.md). Use different scales for adjacent groups and a short final group. Distinguish scheduling metadata from numerical scale ownership.
