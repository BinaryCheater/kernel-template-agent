# 24 拆解参考实现：怎样检验覆盖

KTA 不预设一组固定的设计范畴。覆盖靠持续拆解真实的 SOTA 实现来检验：能拆成已有 Template 组合链的部分，就是已覆盖；拆不出来的部分，就是缺口，补上即可。

本文讲方法；agent 实际操作时读 skill [decompose-kernel](../../src/kta/agents/skills/decompose-kernel/SKILL.md)。

## 1. 为什么可以这样检验

任何一个具体 kernel，都可以从底层往上读：每次用反向映射 π 抽象掉一层细节，最后回到 workload。每个抽象步骤，都对应一个细化步骤。

所以：

- 能被写成一串已有 Template 的组合 → 这个 kernel 在我们的空间里；
- 某一步找不到对应的 Template → 缺一个 Template。而且它的位置是确定的：在哪一层、细化的是哪种模式；
- 某个事务连模式都描述不了 → 缺一个模式，先记为 `other`。

这不能证明 KTA 的范畴是完整的，但每个缺口都能被发现、被定位、被补上。覆盖率随拆解的数量变化，可以在前端看到（21 §2）。

## 2. 拆解的步骤

1. **冻结并实测。** 冻结来源，在 GB10 上按我们的协议构建、检查、测量（不能在 GB10 上运行的，标为"仅分析"）。
2. **写出 workload。** 这个 kernel 计算什么：输入、输出、dtype、形状参数、允许的误差。
3. **列出它在硬件上的事务。** 从源码、SASS、profile 中读出：
   - 计算：哪些归约、收缩、逐元素运算，用什么指令；
   - 存储：每个中间值放在哪一级、什么布局、几份；
   - 搬运：在哪些层级之间，用什么方式（同步 load、cp.async、TMA……），何时发出、何时等待；
   - 同步：哪些屏障，保护什么；
   - 执行者：哪些 warp 或线程做哪些事。
4. **从上往下排出细化链。** 从 workload 开始，每一步问：这里把哪个粗事务替换成了哪些细事务？引入了什么新对象？有哪些变量？对每一步：
   - 在池中检索 refines 同一模式、Γ 成立的 Template；
   - 找到 → 记下链项，写出变量取值；
   - 找不到 → 写一条 Gap，说明这一步细化了什么、引入了什么对象、义务大概是什么。
5. **记录未匹配的事务。** 第 3 步列出的事务中，没有被任何链项覆盖的，逐条记下。这是检验链是否完整的关键：链应该解释所有事务。
6. **复现（若可行）。** 如果所有步骤都匹配上，用某个族的生成器按这组取值生成 kernel，检查正确性，测量性能，与原实现对比。

产出：一条 Reconstruction 记录，包含链、匹配率、Gap 列表、未匹配事务、复现结果。

## 3. 示例（凭记忆，需读源码核实）

### 3.1 Ampere 风格 GEMM（mma.sync、cp.async、多级流水）

| 步 | 细化 | 对应 Template |
| --- | --- | --- |
| 1 | 输出按 (BM, BN) 分块，归约按 BK 分组 | 归约划分；输出分块与映射 |
| 2 | A、B 的 tile 放入 shared memory，带 swizzle | 物理存储；布局与 swizzle |
| 3 | 搬运改为 cp.async 的发出与等待 | 异步传输 |
| 4 | 多级环形缓冲，提前 P 个 tile | 多缓冲轮转 |
| 5 | warp 级 tile 映射到 mma.sync 片段 | 计算指令选择；寄存器片段布局 |
| 6 | 光栅化顺序（swizzle 块序以提高 L2 命中） | 块调度顺序 |

### 3.2 Hopper/Blackwell 风格融合 attention

| 步 | 细化 | 对应 Template |
| --- | --- | --- |
| 1 | softmax 的两遍归约改为单遍在线归约 | 在线归约（reduce，合并可重新缩放） |
| 2 | QKᵀ、softmax、PV 融合进同一 kernel，S 不写回显存 | 算子融合 |
| 3 | Q 按行分块，沿 KV 迭代 | 输出分块与映射；归约划分 |
| 4 | K、V 通过 TMA 搬运到 smem | 异步传输（方式＝TMA） |
| 5 | KV 多级环形缓冲 | 多缓冲轮转 |
| 6 | 加载、MMA、softmax 分配给不同 warp | 执行者绑定（warp 特化） |
| 7 | 两个 Q 块交替，softmax 与 MMA 重叠 | 双组交替调度 |
| 8 | 累加放 TMEM（Blackwell） | 物理存储（层级＝TMEM） |
| 9 | 用 tcgen05.mma 或 wgmma | 计算指令选择 |

这里可以看到，"warp 特化""两组交替"这类做法会同时改变多个事务。它们能否拆成若干个绑定步骤，还是需要一个同时细化多个事务的 Template，正是拆解要回答的问题。两种结论都可以接受，按实际情况在模式表和 Template 中补上即可。

## 4. 首批拆解对象

选择原则：差异大，覆盖不同的算子和硬件代际。

| 对象 | 主要检验什么 |
| --- | --- |
| 一个 CUTLASS GEMM（Ampere 风格，可在 GB10 上运行） | 基础的分块、存储、异步传输、多缓冲 |
| FlashAttention-2 | 在线归约、融合 |
| FlashAttention-3 或 4（多半只能分析，无法在 GB10 上运行） | warp 特化、重叠、新指令 |
| Marlin | 量化反量化与计算的融合、权重预重排 |
| FlashInfer decode | 运行时负载均衡的 split、合并 |
| 一个 grouped GEMM（MoE） | 不均匀分组、运行时元数据 |
| RMSNorm 或 softmax 单独实现 | 行归约、向量化访存 |

## 5. 已经可以预见的难点

拆解时重点留意这些情况。遇到时记录下来，不必事先解决：

- **改变数值的做法**（exp2 近似、FP8 缩放）：义务是误差上界，不是严格等价；
- **依赖运行时数据的划分**（MoE 路由、变长负载均衡）：划分在运行时决定，义务包括元数据正确；
- **同时改变多个事务的做法**（warp 特化）；
- **由编译器决定的事情**（寄存器分配）：不是我们的设计变量，但会影响结果；
- **跨形状分发**：多个赋值加分发规则，是族层面的内容。
