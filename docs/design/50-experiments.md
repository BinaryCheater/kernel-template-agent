# 50 实验与证据

## 1. 实验设计

### 1.1 结论与推翻条件

| 结论 | 怎样算成立 | 什么结果推翻它 |
| --- | --- | --- |
| 摊销 | 池子越大，新 case 的 token、时间和实测次数越少；弱模型＋池子接近强模型从零构造 | 成本不随池子下降；弱模型＋池子明显落后 |
| 覆盖 | M 个参考实现中，N 个能复现，性能在 ε 以内 | N/M 很低，或缺口集中在无法表达的结构上 |
| 饱和 | 依次加入参考实现时，每个需要新增的 Template 数呈下降趋势 | 曲线不下降 |
| 预测 | 留出点上 top-k 召回达到阈值 | 召回接近随机 |
| 质量 | 留出 case 上的 %下界，以及相对最强参照的加速 | 落后于参考实现，且差距无法解释 |
| 可诊断 | 注入已知故障，系统正确归因的比例 | 比例低 |

### 1.2 实验臂

- **知识条件**：从零构造 / 文字知识 / Template 池（见 20 §5）。另设"复制旧配置"作为参照。
- **积累程度**：第 0、n、2n… 个参考实现之后的快照。
- **模型**：一个强模型、一个弱模型。型号由你指定，实验期间冻结。
- **重复次数**：每个 case、每臂 5 次独立运行。预算不足时，优先减少 case 数，不减重复次数。

### 1.3 Case 与数据划分

- 覆盖维度：dense GEMM；量化 GEMM/GEMV（W4A16、FP8）；attention prefill 与 decode；MoE grouped GEMM；norm 与小范围融合；batch 从 1 到较大；序列从短到长。
- **留出集在建池之前冻结。** 扩展和改进都不能用它。被用于修订过的点改记为开发数据，另选留出点。
- **训练数据污染**：留出集中要有一部分新颖任务，例如不常见的融合、非常规的形状或 dtype、模型知识截止日期之后才出现的 kernel。

### 1.4 成本口径

- 各臂的墙钟时间、GPU 时间、步骤数上限相同。token 与费用由会话存档事后分析（你的工具或之后补的脚本）；订阅与 API 两种方式的用量口径不同，比较时分开报告。
- 报告两种成本：每个新 case 的边际成本；包含建池成本的累计成本，以及相对从零构造的盈亏平衡点。
- 失败运行、基础设施修复、共享开发的成本单独列出。
- 有人工改动的运行单独标记，不进入主表。

### 1.5 协议与结果

- 每批实验开始前，在前端批准并冻结协议：case、臂、预算、判据，以及 AgentProfile 版本。各臂的上下文清单只能在协议声明的字段上不同（10 §4.10）。运行中改协议须记录原因，改动前后的结果分开。
- 所有运行都保留并报告，包括失败的，不挑选结果。
- "超越参考实现"须同时满足三条：
  1. 同一协议下实测；
  2. 找到的点在参考实现的设计之外；
  3. 能用空间里的变量解释收益。

## 2. 测量协议

| 项 | 默认做法 |
| --- | --- |
| 计时 | CUDA events；需要细分时用 CUPTI |
| L2 | 每次迭代前写一块至少两倍于 L2 容量的缓冲区 |
| 输入 | 至少 4 组输入轮换使用 |
| 输出 | 每次运行前填充 NaN |
| 预热 | 至少 10 次迭代或 50 ms |
| 正式测量 | 至少 100 次迭代或 200 ms，取较长者 |
| 统计 | 中位数，bootstrap 95% 置信区间 |
| 比较 | 两个实现按随机顺序交错执行 |
| 环境 | 记录时钟、温度、功耗；能锁频就锁频，不能则检查测量期间是否降频 |
| 显著性 | 置信区间不重叠，且差值大于噪声底的 3 倍 |
| 内存 | cudaMalloc，不用 managed memory |
| 独占 | 正式测量期间持有 GPU 安静租约 |

## 3. 正确性检查

- 参考结果在 GPU 上用 FP64 计算。大形状的 FP64 成本过高时用 FP32，并在记录中注明。
- 判据：逐元素 |y − ref| ≤ atol ＋ rtol·|ref|，同时检查整体相对 L2 误差。容差按 dtype 设定，FP16 暂用 rtol = atol = 1e-2。
- 输入分布：随机正态、全零、放大的极端值、按算子设计的对抗输入（例如 attention 中末尾 token 占主导）。
- 边界形状：长度 1、非 tile 整数倍、空的 MoE expert、最大长度。
- 隐藏形状集由检查器用私有种子生成，agent 看不到。
- 小形状上运行 compute-sanitizer 的 memcheck 和 racecheck。

## 4. 族的空间验证

族要被复用，所有合法 assignment 都必须正确。验证分三层：

1. **结构路径覆盖**：结构变量的每条可达路径，都在边界形状集上完整检查一次。
2. **随机抽样**：每条结构路径再随机抽 4 个合法 assignment 检查。
3. **选中即全检**：准备进入实测或结果表的点，必须通过包括隐藏形状在内的完整检查。

此外，manifest 中每个变量都标注数值风险。检查器据此加入对应的输入分布，例如 split 必须测 extreme logits。

第 1、2 层都通过后，Template 才达到"空间已验证"，其结果才能进入正式结论。

## 5. 反作弊检查

| 作弊方式 | 自动检查 |
| --- | --- |
| kernel 内部调用库 | CUPTI 追踪只允许出现声明的 kernel；检查符号表 |
| 复用上次的输出 | 输出预填 NaN；输入每次随机化 |
| 放宽容差或改合同 | Contract 用 hash 固定；agent 没有写权限 |
| 换掉 baseline | baseline 身份固定 |
| 只在测试形状上正确 | 隐藏形状集 |
| 静默回退到通用实现 | 运行时记录实际执行的路径，与声明的 assignment 比对 |

## 6. 理论下界与硬件模型

- 最少工作量 = 语义上必需的 FLOPs，加上每个输入读一次、每个输出写一次的字节数。
- 峰值用 microbenchmark 的实测值。厂商标称值单列，作为对照。
- 下界 = 各单元"最少工作量 ÷ 峰值"中的最大值；%下界 = 下界 ÷ 实测时间。
- Nsight Compute 的 SOL% 用来诊断瓶颈在哪个单元，不能替代下界。
- GB10 的 microbenchmark 至少覆盖：DRAM、L2、shared memory 带宽；各级延迟；各 tensor core 指令与 dtype 的吞吐；bank 行为；TMA 可用性；L2 容量；启动开销；持续负载下的时钟。

## 7. 性能模型

- **编译前**：按硬件单元计算工作量，除以峰值，取最大值，再加上不能重叠的项（启动、prologue/epilogue、同步、wave 量化）和校准得到的交互项。
- **编译后**：用编译反馈（寄存器、spill、smem）修正 occupancy 和延迟隐藏能力。
- **精度目标是排序**：主要指标是 top-k 召回，其次才是绝对误差。
- 两个变量同时变化的组合误差显著时，加入交互项，不把误差摊进其他系数。
